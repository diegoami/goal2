# T07 The quick engine on an adapter-roundtripped state: prove the adapter is faithful enough for the vendored engine

- **Kind**: slice
- **Issue**: #<new>
  **Branch**: `task/T07-engine-on-adapted-state` · **Merge after**: T06
- **Implementer**: the main session
- **Reviewer**: `luna` (the integration test is a measurement, not an engine seam; the lighter reviewer fits)
- **Evidence**: E010 (the ten quick-engine half-time savestates from archaeology). T01's vendored quick engine runs on a half-time savestate. T06's state adapter reads a savestate into a `GameState` and writes it back. This task proves the adapter is faithful: the vendored engine produces the same result on a roundtripped state as on the original.
- **Owns**: `goal2/tests/test_engine_on_adapted_state.py` (the integration test: run the quick engine on E010-r0001's original state and on the adapter-roundtripped state, compare the results).
- **Scope**:
  1. The integration test: loads E010-r0001 (a half-time savestate), runs the vendored quick engine (T01) on it, and records the result (score, goals, seed words). Then reads the savestate through the adapter (T06), writes it back, runs the engine on the roundtripped state, and compares the result. The two results must be identical.
  2. The test must work with any E010 record (r0001..r0010), not just r0001.
  3. The test skips with the reason when E010-r0001 is not fetchable.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_engine_on_adapted_state` is green (skipped when the fixture is absent).
  2. For E010-r0001: the vendored engine produces the same score, goals, and seed words on the original and on the adapter-roundtripped state.
- **Hazards**:
  - the vendored engine reads VGA and Memory components; the adapter must preserve both (T06 does this);
  - the vendored engine reads the RNG words (DS:7B62, DS:8336); the adapter must preserve them (T06 does this);
  - the integration test must not commit a savestate (rule 19); it reads from `.cache/`, which is git-ignored.
