# T154 Evaluate one clean UI/engine boundary

[designed: owner, 2026-11-02, #524] Absorbed by T158 (the technology choice of the design phase), whose point 3 is this
task's scope. Kept as the record of #516.

- **Kind**: evaluation (no change to the game)
- **Issue**: #516 · **Branch**: `task/T154-boundary` · **Merge after**: T153 (post-playable)
- **Evidence**: [designed: owner, 2026-11-02, #516] The Qt window runs under CPython (PySide6 has no PyPy
  build). The sealed port plays about four times faster under PyPy 3.11 [confirmed: goal2-archaeology #620].
  So matches run in other processes, over two file-based channels:
  - the watched and competitive worker: a length-prefixed JSON journal, polled every 30 ms
    (`goal2/game/watched_jobs.py`);
  - the quick-match worker: whole JSON files (`goal2/desktop/jobs.py`, `goal2/desktop/worker.py`).

  The pitch viewer is a third process (`goal2/desktop/watched.py`, `goal2/desktop/core_viewer.py`). #503 was a
  bug of this design. The owner approved evaluating a redesign before choosing one: option 3 of #516 (one
  long-lived PyPy engine process over one pipe protocol) and option 4 (goal2rust as a CPython module).
- **Owns**:
  - `docs/redesign-516/boundary.md`
  - `tools/boundary_probe.py` (the latency measurement and the throwaway pipe prototype)
  - `measurements/T154/`
- **Scope**: Measure and write up; change no game code. The write-up covers:
  1. **Inventory.** Every process boundary and every message type that crosses it, with its file and line.
  2. **History.** The bugs and flaky tests these channels caused, from the issue and PR history, each with its
     link.
  3. **Measurements**, on Linux and on Windows, at least 5 runs each, for both today's channel and a minimal
     prototype of option 3's pipe (a PyPy child that stays up and answers over stdin/stdout):
     - process start;
     - time to the first event of a watched match;
     - per-event latency.
  4. **Option 3's design.** The protocol (requests, replies, cancellation, a crash of the engine process),
     what it replaces, and which tests change. Also a cost estimate in tasks.
  5. **Option 4's needs from goal2rust.** Its API, threading (releasing the GIL), and the build in the
     portable ZIP.
  6. **Recommendation**, for the owner to decide.
- **Done when**:
  1. `docs/redesign-516/boundary.md` holds sections 1–6. Every inventory row names a file and line that
     exist at the merged commit.
  2. `measurements/T154/*.json` hold the raw timings for both platforms and both channels. The write-up's
     tables are computed from them by `tools/boundary_probe.py summarize`, and the command is quoted.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes.
  4. Linux and Windows are green.
- **Review**: the owner decides on #516 from the write-up.
- **Hazards**:
  - Timing on a loaded PC: run the probe with nothing else heavy on it, and record the load.
  - A prototype that grows into the redesign. It stays in `tools/` and plays no real match through the UI.
