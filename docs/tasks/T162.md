# T162 The new window's foundation: look, screen stack, import and help

- **Kind**: feature
- **Issue**: #536 · **Branch**: `task/T162-ui-foundation` · **Merge after**: T158
- **Evidence**:
  - [designed: owner, 2026-11-03, #526] The screens and the rules for the whole UI are in
    `docs/design/ui-2026-11/README.md`: sections 1 and 3, S01 and S22. The mockups are
    `docs/design/ui-2026-11/mockups/*.html` and `style.css`.
  - The palette is the README's §3 table, read by `palette.py`.
  - The font is PxPlus IBM VGA 8x16 (CC BY-SA 4.0), vendored in `docs/design/ui-2026-11/mockups/fonts/` with its
    LICENSE and PROVENANCE.
  - [designed: owner, 2026-11-03, #527, D1] The toolkit is PySide6 widgets (Essentials).
  - Today's import logic is `goal2/desktop/data_setup.py` (T153, #531, GOAL.HLP optional).
  - GOAL.HLP is CR LF text, 32,569 bytes. The pinned hash is in `data_setup.OPTIONAL`, and the format is quoted in
    goal2-archaeology `sources/goal-hlp.md`.
- **Owns**:
  - A new package, `goal2/ui/`: the new window. It sits beside `goal2/desktop/`, which stays the shipped window
    until T169.
  - The font copied into the package with its LICENSE and PROVENANCE.
  - `goal2/tests/test_ui_foundation_t162.py`.
  - `docs/ui.md`, a short guide to the new window's structure.
  - Package data in `pyproject.toml` for the font.
- **Scope**: The base the screen tasks T163–T168 build on, plus the two screens that need no game: S01 and S22.
  The task protects one claim: **every screen is drawn in the original's palette and the VGA font, says what it
  waits for, and works with both keys and mouse.**
  1. **The look.**
     - One theme module holds the design's colours, by role, as named constants equal to the README's §3 table.
     - The vendored font is loaded with `QFontDatabase` from package data, never from a system install.
     - Text sizes are whole multiples of the 16 px cell. The page scales as a whole with the window, as the
       design's text-size rule says.
  2. **The screen stack.**
     - One main window holds one screen at a time.
     - A `Screen` base class gives each screen: a title bar (the GOAL2 corner and the screen's name); a bottom bar
       listing every key of the screen, with the Enter hint at its right end drawn as the original's highlight
       bar; and an optional "waiting for" line for stops.
     - Navigation is push, pop and replace-home. Esc returns where the design says.
     - A clickable option does exactly what its key does, through the same handler.
  3. **S01, Import your data.** The first-start screen over `data_setup`'s existing check and copy, restyled as the
     S01 mockup:
     - each file's check on screen (present, missing, wrong);
     - GOAL.HLP shown as optional;
     - the plain-words errors kept.
     No change to `data_setup`'s rules.
  4. **S22, Help.**
     - F1 on any screen opens the original's help text from the imported GOAL.HLP, decoded as code page 437, in
       the VGA font, scrollable. Esc closes it and returns to the screen it was opened from.
     - With no GOAL.HLP imported, F1 says so in plain words and how to add it (re-import the folder).
     - No byte of GOAL.HLP enters the repository or the tests' committed files. Tests write a stand-in help text
       of their own into a temporary data folder.
  5. **An entry point.** `python -m goal2.ui` opens the new window: S01 when the data folder is not imported, or
     otherwise a placeholder home screen. T163 replaces the placeholder with S02. The portable build's launcher
     and default stay unchanged.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_ui_foundation_t162 -v` passes offscreen, and fails on `main` because the
     package does not exist. It shows:
     - **The palette:** the theme's colours equal the README §3 table, parsed from the README itself.
     - **The font:** the application font's family is the vendored PxPlus font, loaded from the package path.
     - **The stack:** a test screen pushed and popped with Esc returns to the previous one. Its bottom bar lists
       its keys, and the Enter hint shows the highlighted option's action.
     - **Mouse equals key:** clicking an option and pressing its key call the same handler with the same result.
     - **S01:** with a temporary folder missing GOAL.DAT, S01 shows it as missing and refuses to continue. With a
       complete stand-in set (the test's hashes patched, as `test_import_help_hlp` does), it imports and
       continues. A wrong optional GOAL.HLP is refused, and a missing one is accepted.
     - **S22:** F1 opens the help with the stand-in text, and Esc returns to the same screen. Without GOAL.HLP, F1
       shows the plain-words message.
  2. `QT_QPA_PLATFORM=offscreen python3 -m goal2.ui --screenshot <dir>` (or an equivalent tool under `tools/`)
     writes PNGs of S01, S22 and the placeholder home. The PR embeds them next to the S01 and S22 mockups, so the
     look can be compared.
  3. Existing desktop tests are unchanged and pass.
  4. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows and Linux green.
- **Review**: none (the owner sees the screenshots in the PR; m3 milestone review).
- **Hazards**:
  - **Restyling the old window.** `goal2/desktop/` is left alone. The new window is built beside it, and T169
    switches over.
  - **Inventing a look.** Use the mockups' colours, sizes and layout, not new ones. A departure from the mockups
    is a design question for the owner.
  - **Original bytes.** No GOAL.HLP text, not even a quotation, in tests or fixtures (CLAUDE.md rule 14).
  - **Font licence.** CC BY-SA 4.0 needs its LICENSE shipped next to the font in the package and in the portable
    build.
