# T170o Retain the season in the existing PyPy worker

- **Kind**: first worker-activation leaf of T170 (#566); **Issue**: #735.
- **Branch**: `task/T170o-season-worker`; **Merge after**: T170n/#733.
- **Evidence**: [confirmed: T170b] `SeasonSession` owns the actual pending Match,
  continuation and persistent Keys. [confirmed: T170n] `PrematchSeam` configures
  that Match once and answers the original's pre-match decision. [designed:
  owner #527 D3, T159] Reuse the existing PyPy process and bounded JSON/binary
  packet transport; the CPython window never runs the engine.
- **Owns**: season request handling and its client in `goal2/game/`, focused
  worker tests and `docs/engine-process.md`. No window, save format or engine edits.
- **Scope**: explicitly open accepted state/2 in one worker-owned session;
  advance/observe it, configure its actual pending Match through PrematchSeam,
  return bounded events stopping at every decision, accept a numbered answer,
  and resume only that same completed Match. Never step past an unanswered
  decision (Match.events otherwise answers by default). Detached observations
  carry exactly-once fixture/news deltas and state hashes. Discard/death ends
  the transient session; reopening is explicit, never automatic replay. The
  legacy match API remains available when no season is open. Window activation,
  pitch pacing and active save/load semantics follow in separate leaves.
- **Done when**:
  1. `python -m unittest goal2.tests.test_season_worker_t170o -v` fails before
     implementation and passes after. Controls prove one session and Keys across
     calls, same-Match resume, bounded events/decision waits, stale/duplicate
     answers and early resume refusal, deltas, terminal repeat, discard, death
     without replay and exclusion of legacy match/open while a season is held.
  2. A source-bound PyPy control compares the actual held entry to a direct
     SeasonSession (full memory/all sixteen registers), then configured pre-match
     decisions and edit/play events against direct answers. An actual pipe
     process reports PyPy 3.11 and returns matching observations/decisions.
     No complete match runs in CPython; original bytes remain private.
  3. `python3 tools/check_premerge.py --expected-head <sha>` and required CI pass.
     Full slow suites belong to the integrated milestone dispatch.
- **Review**: owner's m3 milestone; no per-PR review requested.
- **Hazards**: constructing a fresh Match, implicitly playing on at a decision,
  replaying open after death, sharing child-owned dicts, or treating a pending
  Match's state as a completed/publishable round.
