# T08 Both halves of a quick match from goal2's own state: run the engine twice (the first half assumed to run as the second, A-MATCH-1)

- **Kind**: slice
- **Issue**: #20
  **Branch**: `task/T08-both-halves` · **Merge after**: T07
- **Implementer**: the main session
- **Reviewer**: `luna` (the test is a measurement, not an engine seam; the lighter reviewer fits)
- **Evidence**: [confirmed: E010, T01, T07] E010 (the ten quick-engine half-time savestates). T01's vendored quick engine runs the second half from a half-time state. The plan's A-MATCH-1 says "the first half assumed to run as the second": the same code runs both halves. This task runs the engine twice on the same half-time state (the first run produces the "first half" result; the second run, starting from the first run's output state, produces the "second half" result). The combined result is the full match.
- **Owns**: `goal2/tests/test_both_halves.py` (the test: run the engine twice on each E010 record, verify the combined result is reproducible).
- **Scope**:
  1. [confirmed: E010, T01, A-MATCH-1] The test: for each E010 record, run the vendored quick engine (T01) on the half-time state and record the result (score, goals, seed words). Then take the result and run the engine again (treating the first run's output as a new half-time state). The second run uses the same code path (A-MATCH-1).
  2. [designed] The combined result: the full-match score is the sum of the two halves' scores. The goals list is the concatenation of the two halves' goals (with adjusted minutes: second-half minutes = 45 + first-half minutes).
  3. [confirmed: F004, T01] The reproducibility check: running the engine twice on the same input must produce the same combined result (the engine is deterministic from its seed words).
  4. [designed] The test must work with any E010 record (r0001..r0010), with r0001 as the primary record.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_both_halves` is green (skipped when the primary record is absent).
  2. For E010-r0001: running the engine twice produces a reproducible combined result (same score, goals, seed words on repeated runs).
- **Hazards**:
  - [confirmed: rule 18] the vendored engine is read-only; T08 does not modify it, it only calls `simulate` twice;
  - [designed] the first run's output state must be valid for a second run (the engine reads VGA, Memory, and the RNG words; the output state should be a valid savestate);
  - [confirmed: rule 19] the test must not commit a savestate; it reads from `.cache/`, which is git-ignored.
