# T13 The tactics screen: 8 team tactics bits, toggleable, write to state

- **Kind**: feature
- **Issue**: #30
  **Branch**: `task/T13-tactics-screen` · **Merge after**: T12
- **Implementer**: the `implementer` subagent on `haiku` (this session runs on MiniMax; `haiku` resolves to MiniMax-M2.7, the light model — T10/T11/T12 worked on this alias)

- **Evidence**:
  - F010 (proposed): `country[+0x2D]` is a Pascal set of 8 team tactics, element k at bit k − 1. The tactics screen prints all 8 in the order `DS:6BC0` = 5, 6, 7, 1, 2, 3, 4, 8 (each row's "clear" and "set" words at `DS:6AA0 + 32·k + 16·bit`). Element labels: 1 "position" (stay back / push forward), 2 "possession" (keep ball / quick pass), 3 "passing" (short passes / long passes), 4 "tackling" (avoid injury / go in hard), 5 (half pitch / full pitch), 6/7/8 (other; the screen labels of 5..7 are not read in F010).
  - T11 (country select): the chosen country's record is the 0xBF byte array at `state.countries[managed_country]`; byte +0x2D holds the 8 bits.
  - T12 (squad select): `state.starting_eleven` and `state.captain` are set; the tactics screen reads them implicitly (the squad view's tactics come from `+0x2D`, which the screen now mutates).
  - T10 / T11 (framework + input): the screen reuses `goal2.ui.grid.Grid`, `goal2.ui.input.Key`, and the `run_*_select(...keys, state...) -> bool` pattern.
- **Owns**: `goal2/ui/tactics.py` (the screen); `goal2/tests/test_tactics.py`. **Also extends** `goal2/engine/state.py` with one new `GameState` field (`country_tactics`) — default `0` so existing tests still pass. The adapter's `to_savestate` does not write `country_tactics` in v1 (a follow-up task will plumb it through `to_savestate` and the round-trip test).
- **Scope**:
  - `GameState` grows one field with a safe default:
    - `country_tactics: int = 0` — the 8-bit team tactics byte. Default 0 means "all bits clear". The field is set by T13's screen on Enter and read by future tasks (T14 match, the watched engine). [designed: T13 only writes; downstream tasks consume]
  - The tactics screen (`goal2.ui.tactics.run_tactics_select`):
    - Signature: `run_tactics_select(goaldat: GoalDat, keys: Iterable[Key] | None, *, state: GameState | None = None, initial_tactics: int | None = None) -> bool`
    - Returns `True` on Enter (tactics confirmed), `False` on Esc (no change).
    - The initial 8-bit value is read from `initial_tactics` if given, else from `state.country_tactics` if `state` is given, else 0. The screen mutates a local copy as the user toggles; only on Enter does it write back to `state.country_tactics`. Esc leaves `state` untouched.
    - When `keys` is `None`, the screen calls `read_key()` in a loop (T11's pattern). When provided, it iterates scripted keys.
    - Display order (per F010's `DS:6BC0`): rows in the order 5, 6, 7, 1, 2, 3, 4, 8 — i.e., element 5 first, then 6, 7, 1, 2, 3, 4, 8 last. Each row's bit position is `element − 1`.
    - Cursor starts at row 1 (display row 1 = element 5, bit 4). `Up` / `Down` move by ±1; clamps at 1 and 8.
    - `Space` (or any key that is not `Up`/`Down`/`Enter`/`Esc` — keys are the screen's own abstraction): toggle the bit at the cursor's element. The cursor does not move.
    - `Enter`: if `state` is given, set `state.country_tactics = current_byte`. Then return `True`.
    - `Esc`: return `False`. If `state` is given, leave it untouched.
  - Rendering (the test surface):
    - Title row 0: `TACTICS  0xNN` where `0xNN` is the current 8-bit byte in hex. [designed: a live preview of the byte the screen is about to write]
    - Body rows 1..8: one element per row. Format: `[X]  <clear> / <set>` where `[X]` is the toggle marker (`X` if bit set, ` ` if clear), and the slash separates the two label strings. The cursor row uses reversed video (`draw_text(..., fg=0, bg=7)`).
    - Footer row 24: `↑↓ MOVE  SPACE TOGGLE  ENTER PICK  ESC QUIT`. [designed]
    - Element labels (display order, per F010):
      - Element 5: `half pitch / full pitch`
      - Element 6: `short kicks / long kicks` [designed: a plausible label; F010 notes the screen labels of 5..7 are not read in the original archaeology]
      - Element 7: `stay back / push forward` [designed: same caveat]
      - Element 1: `stay back / push forward`
      - Element 2: `keep ball / quick pass`
      - Element 3: `short passes / long passes`
      - Element 4: `avoid injury / go in hard`
      - Element 8: `zone / man to man` [designed]
  - Out of scope: the **player-level overrides** at `player[+0xF]` (per F010 — players can override elements 1..4 of the team's tactics) — a follow-up task; reading the original country byte +0x2D for the initial value — `initial_tactics` overrides `state.country_tactics`, and the screen accepts the byte as a parameter; persisting `country_tactics` through `to_savestate` — a follow-up.
- **Done when**:
  1. `python -m unittest goal2.tests.test_tactics` is green.
  2. `test_tactics` asserts, with a `GoalDat` and a `GameState` constructed via `_make_state()`:
     - Initial tactics 0x00 → 8 rows render with `[ ]` (all bits clear). `initial_tactics=0xFF` → 8 rows render with `[X]`.
     - `run_tactics_select(goaldat, [SPACE, ENTER], state=state, initial_tactics=0x00)` returns `True`, sets `state.country_tactics == 0x01` (bit at display row 1 = element 5 = bit 4, but the screen's local toggle applies to the *element* at the cursor, not the bit position. Adjust: cursor starts at display row 1 = element 5 = bit 4. `SPACE` toggles bit 4 → byte becomes `0x10`. `ENTER` writes `0x10`. The Done-when test verifies `state.country_tactics == 0x10` after `[SPACE, ENTER]` from `initial_tactics=0x00`).
     - `run_tactics_select(goaldat, [DOWN, SPACE, ENTER], state=state, initial_tactics=0x00)` toggles the bit at display row 2 (element 6, bit 5) → byte becomes `0x20`.
     - `run_tactics_select(goaldat, [DOWN] * 3 + [SPACE, ENTER], state=state, initial_tactics=0x00)` toggles display row 4 (element 1, bit 0) → byte becomes `0x01`.
     - `run_tactics_select(goaldat, [ESC], state=state, initial_tactics=0xAA)` returns `False` and does not touch `state.country_tactics` (the test pre-sets `state.country_tactics = -1` and asserts it survives).
     - The expected `state.country_tactics` after each scripted key sequence is computed from the cursor movement + toggle arithmetic — so deleting the Space handler makes the test fail (byte stays at `initial_tactics`).
  3. The render surface test calls a private `_render(goaldat, state, byte, cursor) -> Grid`:
     - The cursor row's content starts with `[X]` or `[ ]` matching the bit at the cursor's element in the input `byte`. The expected marker is computed from `byte` and the cursor's element — replacing the bit lookup with a hardcoded `[X]` fails.
     - The title row holds `f"TACTICS  0x{byte:02X}"` — the byte is from the input.
     - Add a second render test with `byte=0x55` to catch a hardcoded byte in the title.
  4. After Enter, `state.country_tactics` is one of the 256 possible byte values (assert `0 <= state.country_tactics <= 0xFF`).
- **Hazards**:
  - "Test passes with the grid deleted" (lesson from T05/T09/T10/T11/T12 review rounds): the expected `state.country_tactics` is computed from cursor + toggle arithmetic, not a hardcoded literal — so deleting the Space handler fails the test.
  - "Cursor bit arithmetic is confusing" — display row 1 is element 5 (bit 4); display row 4 is element 1 (bit 0). The test must compute the expected byte from the cursor movement through the display order, not assume "row 1 = bit 0". Pin the bit-position mapping explicitly in code (`_BIT_OF_ELEMENT = {1: 0, 2: 1, 3: 2, 4: 3, 5: 4, 6: 5, 7: 6, 8: 7}` and `_DISPLAY_ORDER = (5, 6, 7, 1, 2, 3, 4, 8)`); the test asserts the byte against `initial_tactics ^ (1 << _BIT_OF_ELEMENT[_DISPLAY_ORDER[cursor - 1]])`. Mutation: hardcoding "row 1 = bit 0" makes the test fail.
  - "State write is silent": Esc must leave `state.country_tactics` untouched. The test pre-sets `state.country_tactics = -1` and asserts it survives. Mutation: making Esc return `True` makes the boolean check fail; making Esc write state makes the sentinel check fail.
  - "Off-by-one at the boundary" (lesson from T11/T12): clamps at display row 1 and 8; `Up` at row 1 is a no-op; `Down` at row 8 is a no-op. Add a `[UP, UP, SPACE, ENTER]` test from `initial_tactics=0x00` (clamped at 1 → element 5 → bit 4 → byte 0x10) and a `[DOWN]*10, SPACE, ENTER` test (clamped at 8 → element 8 → bit 7 → byte 0x80).
  - "GameState field default safety": existing tests construct `GameState` with positional args; adding one new field with a default must not break them. Verify by running the full test suite (`python -m unittest goal2.tests`) — any failure there is a T13 regression.
