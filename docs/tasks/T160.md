# T160 Watched and competitive matches on the engine pipe

- **Kind**: infrastructure
- **Issue**: #534 · **Branch**: `task/T160-matches-on-pipe` · **Merge after**: T159
- **Evidence**:
  - [designed: owner, 2026-11-03, #527, D3] One long-lived PyPy engine process over a pipe
    (`docs/design/technology-2026-11/README.md` §3.4). T159 built it: `goal2/game/engine_process.py`,
    `goal2/game/engine_server.py`, `docs/engine-process.md`.
  - Today the Python route's watched and competitive matches go through the file-journal bridge B1:
    - `goal2/game/watched_jobs.py` `WatchedJobs`, used by `goal2/desktop/watched.py:92` `WatchedController`;
    - `goal2/desktop/competitive.py` `CompetitiveJobs`, a subclass;
    - each match spawns `goal2.game.watched_worker` or `goal2.desktop.competitive_worker` under PyPy.
  - The bugs B1 caused are in the technology design's §3.2. #417 is a worker that outlives its window.
- **Owns**:
  - `goal2/game/watched_jobs.py`: the bridge classes' transport.
  - `goal2/desktop/competitive.py` and `goal2/desktop/watched.py`, only where they construct or call the bridge.

  - `docs/watched-jobs.md` and `docs/engine-process.md`.

- **Scope**: The Python route's watched and competitive matches play on T159's engine process, not on a worker per
  match over file journals. The task protects one claim: **the window sees the same match through the same bridge
  API as before.** That means the same events, pitch samples, bench decisions, outcome, publication-once, cancel
  and close behaviour. Only the transport underneath changes.
  1. **One engine process per open game (owner).** `WatchedJobs` and `CompetitiveJobs` share it. It is started
     lazily at the first match, sent the game with `open` once, and re-opened only when the game changed since the
     last `open`, as the existing `_PreparingProcess` input decides today. It is closed with the owner's close.
  2. **The bridge's public API is kept.**
     - Public means `start`, `poll`, `poll_frames`, `ack_frames`, `pause`, `answer`, `cancel`, `cancel_and_reap`,
       `close`, `busy`, `engine_complete`, `frames_drained`, the publication rules and the `token` checks.
     - Replies from the reader thread are queued and drained by the existing `poll` calls, so the window's code
       above the bridge does not change.
     - A token still scopes a match: replies of a cancelled or replaced match are never shown for the next one.
  3. **Engine death.** It is reported through `poll` as the same error kinds the window already handles (the
     worker's exit, its stderr tail). The next `start` gets a new process.
  4. **The stale Unicorn guards go.** `competitive.require_runtime` (`competitive.py:34`) and the `find_spec('unicorn')`
     check in `watched.py:127` refuse a Play that no longer needs Unicorn. They are removed, with their messages, and
     the tests that asserted them are changed to assert that Play starts without Unicorn installed
     (#509's draft T155).
  5. **Out of scope.** The worker modules `watched_worker.py` and `competitive_worker.py`, `_PreparingProcess`, the
     journal reader and writer, and `_remove_folder` stay in the tree, unused by the window. T161 deletes them with
     the quick friendly's move. The pygame viewer (B3) is unchanged; T166 replaces it.
- **Done when**:

       the game sent once while it is unchanged;
     - after the window's model closes, the engine process has exited within 5 s (#417: no worker outlives its
       window);
     - with `unicorn` made unimportable (a meta-path blocker in the test), a competitive Play and a watched Play
       both start and complete.
  2. The B1 behaviour tests pass against the pipe, with assertions unchanged except where an assertion names the

     changed assertion with the reason. The tests are `test_watched_jobs`, `test_watched_pitch_jobs`,
     `test_watched_startup`, `test_watched_completion`, `test_desktop_competitive_jobs`, `test_watched_bench_t102`
     and `test_pypy_worker_t152`, all with `GOAL2_SLOW=1`.
  3. The window tests that go through the poll loops pass unchanged: `test_match_result_t97`,
     `test_reordered_squad_280`, `test_match_prep_t95`, `test_desktop_watched_sharing`.
  4. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows and Linux green, except

- **Review**: none (m3 milestone review).
- **Hazards**:
  - **Two match loops.** The child side is T159's server; do not add match logic to the bridge.
  - **Token leaks.** A reply from a cancelled match arriving after the next `start` must be dropped by the token
    check, not shown. Test it.
  - **Tests that assert transport.** The B1 tests encode files and folders in places. Change only those assertions,
    and list each one; never weaken one that checks what the window sees.
  - **A process per test.** Each test must close its owner, so no engine process survives a test, on Windows
    especially.
