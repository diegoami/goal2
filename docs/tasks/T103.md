- **Scope**:
  - **Waits.** A table maps each key-read **site** (214B:08DD's return address) to a kind.
    - A shared reader site is told apart by the caller frames the original pushed, such as the Y/N questions or the menu reader.
    - Where frames are not enough, the table reads a named memory field through the state adapter. Two cases met so far: the tactics screen's own team or opponent, and the fixture list's highlighted row and its mark. The field is cited from the annotated globals.
    - The text is never used.
    - Each entry cites its routine in the named listings and the record that shows it.
  - **Polled screens.** Some screens read a key only after "key pressed?" (214B:0723) says yes: the captain prompt (`0791:CED9`, then `CEE8`), play (`0791:93BD`, then `93CE`), and the timed save prompt and result pages.
    - Their poll sites are mapped to kinds in the same table.
    - Each wait reports the polled kinds passed since the previous wait (`KeyWait.passed`), with their poll counts.
    - `core.queue(kind, key)` answers the next poll of that kind with the key, which the original then reads. A key the kind does not accept is refused. With nothing queued, a poll answers "no key" as in T100.
  - **Kinds.** Kinds are named as in `kinds.tsv`.
    - A screen that no rule there names gets a `[designed]` goal2 kind, listed in `docs/core.md` with its site and record. Cases met so far: the team-info browser (`1771:28F5` from `000E:7682`), the fixture list on the own match, the half-time board, the match-stats board, the opponent's tactics and the tournament view.
    - Each entry lists the keys the screen accepts, from `catalogue.tsv` (its `screen` and `owner` rows), with each key's code as 08DD returns it. A `[designed]` kind cites its keys from the screen's own printed hints and the listing.
  - **The wait.** `KeyWait.kind` is the kind. A site with no entry raises `UnknownScreen(site, text)`; the runner never guesses.
  - **Views.** Where a screen has a cursor or a selection, its `view` reads it from memory: the menu item, the country browsed, the player selected. Other state views come with the screen task that needs them (G10–G14).
  - **Not reached.** The kinds the core cannot reach yet are listed in `docs/core.md` with the reason:
    - `country-select` (the new-game screens): no kept savestate stops there at an INT 16h read, and leaving the menu calls INT 10h. G10 needs a new-game savestate from goal2-archaeology.
    - Interrupts other than the key reads stay unserved (T100).

- **Hazards**:
  - Never identify a screen from its text in the core. The text rules only check the table.
  - Never press a key a screen does not list.
  - A queued key is answered only at a poll of its kind, never at another screen's poll.
