  - T02 (GOAL.DAT loader): `state.managed_squad[i]` is a 1-based player number; `goaldat.player_names[n]` and `goaldat.player_initials[n]` give the surname and initial at `[DS:9B6C]` / `[DS:9B70]`

- **Owns**: `goal2/ui/squad.py` (the screen); `goal2/tests/test_squad_select.py`. **Also extends** `goal2/engine/state.py` with two new `GameState` fields (`starting_eleven`, `captain`) — fields default-empty so existing tests still pass. The state adapter's `to_savestate` does not write these new fields in v1 (a follow-up task will plumb them through `to_savestate` and the round-trip test).
- **Scope**:
  - `GameState` grows two fields with safe defaults:
    - `starting_eleven: list[int] = field(default_factory=list)` — the 11 player numbers of the chosen starting lineup
    - `captain: int = 0` — the captain's player number (0 means "not yet picked")
    - The fields are set by T12's screen on Enter and read by future tasks (T13 tactics, T14 match). [designed: T12 only writes; downstream tasks consume]
  - The squad select screen (`goal2.ui.squad.run_squad_select`):
    - Signature: `run_squad_select(goaldat: GoalDat, keys: Iterable[Key] | None, *, state: GameState | None = None, page_size: int = 20) -> bool`
    - Returns `True` on Enter (a captain was picked), `False` on Esc (no captain).
    - When `keys` is `None`, the screen calls `read_key()` in a loop (T11's pattern). When provided, it iterates scripted keys.
    - The screen reads `state.managed_squad` (the 20 player numbers T11 set) and `goaldat.player_names` / `goaldat.player_initials` to render each row's name. [confirmed: T11 + T02]
    - The cursor starts at row 1 (the first squad member). `Up` / `Down` move the cursor by ±1; clamps at 1 and `len(state.managed_squad)` (= 20 by default).
    - `Enter`: set `state.starting_eleven = list(state.managed_squad[:11])` (the first 11 player numbers, in country-record order) and `state.captain = state.managed_squad[cursor - 1]` (the cursor's player, regardless of which row — even if the cursor is on a bench slot, the captain defaults to that player; the user is expected to pick from rows 1..11, but the screen does not enforce this in v1). Then return `True`.
    - `Esc`: return `False`. If `state` is given, leave it untouched.
  - Rendering (the test surface):
    - Title row 0: `SELECT CAPTAIN  N` where N is the cursor's row number (1..20). [designed: the original's title bar is unknown; this is the rebuild's]
    - Body rows 1..20: one player per row. Format: ` NN  I SURNAME` (NN is the row number, I is the initial letter, SURNAME is the surname, padded to 12 chars). The captain's row has a ` C` suffix on the right edge of the row (a fixed-width marker, not cursor-dependent — it's the captain after Enter). [designed: the captain marker is post-Enter state; before Enter, no row has a C marker — verified by the test]
    - The cursor row uses reversed video (`draw_text(..., fg=0, bg=7)`).
    - Footer row 24: `↑↓ CAPTAIN  ENTER PICK  ESC QUIT`. [designed]
    - `page_size` defaults to 20 and is clamped to ≤ 23 (T11's pattern; the footer is on row 24).
  - Out of scope: the **pool** view (the 80 extra records per manager from F011) — a follow-up task; swapping players between squad and pool — a follow-up; rearranging the eleven's order — a follow-up (T12 only sets the eleven to the first 11 in country-record order, per SQ-5); persisting `starting_eleven` and `captain` through `to_savestate` — a follow-up (T12 writes the fields in memory; the adapter's byte layout for them is a separate task).
- **Done when**:
  1. `python -m unittest goal2.tests.test_squad_select` is green.
  2. `test_squad_select` asserts, with a `GoalDat` whose `player_names[1..20]` are `"P1".."P20"` and `player_initials[1..20]` are `"A".."T"`, and a `GameState` with `managed_squad = list(range(1, 21))`:
     - `run_squad_select(goaldat, [ENTER], state=state)` returns `True`, sets `state.starting_eleven == list(range(1, 12))`, and sets `state.captain == 1` (the cursor starts at 1).
     - `run_squad_select(goaldat, [DOWN, DOWN, ENTER], state=state)` returns `True`, sets `state.captain == 3`. The expected captain is computed from the cursor movement, not a hardcoded literal — deleting the Down handler makes the test fail (captain stays at 1).
     - `run_squad_select(goaldat, [ESC], state=state)` returns `False` and does not touch `state.starting_eleven` or `state.captain` (the test pre-sets both to sentinel values and asserts they survive). The state must be passed to `run_squad_select` for this assertion to be meaningful.
     - `run_squad_select(goaldat, [UP, UP, ENTER], state=state, page_size=20)` returns `True` and sets `state.captain == 1` (clamped at 1).
     - `run_squad_select(goaldat, [DOWN] * 30 + [ENTER], state=state)` returns `True` with `state.captain == 20` (clamped at 20).
  3. The render surface test calls a private `_render(goaldat, state, cursor, page_size) -> Grid`:
     - The cursor row's content (row `cursor` in the rendered grid, split on `\n`) starts with `f" {cursor:2d}  "` (the row number is computed from the input).
     - The title row holds `f"SELECT CAPTAIN  {cursor}"` (the cursor number is computed from the input — replacing `{cursor}` with `" 1"` hardcoded passes for one cursor value but not for a second test case).
     - Add a second render test with `cursor=15` to catch a hardcoded cursor number in the title.
  4. The captain marker: after Enter, `state.captain` is one of the 20 managed_squad entries (assert `state.captain in state.managed_squad`).
- **Hazards**:
  - "Test passes with the grid deleted" (lesson from T05/T09/T10/T11 review rounds): the captain value and row number are computed from the cursor movement, not literals — so deleting the cursor logic fails the test.
  - "State write is silent": Esc must leave `state.starting_eleven` and `state.captain` untouched. The test pre-sets both to sentinel values (`[-1] * 11` and `-1`) and asserts they survive an Esc. Mutation: making Esc return `True` makes the boolean check fail; making Esc write state makes the sentinel check fail.
  - "Captain row marker is hardcoded" — the captain marker is post-Enter state (a fixed column, not cursor-dependent). The test asserts that after Enter, `_render(goaldat, state, cursor=captain_row, page_size=20)` shows the ` C` marker on the captain row. Mutation: making the marker cursor-dependent (showing it on every cursor row) fails the test.
  - "Off-by-one at the squad boundary" (lesson from F011: 20 squad records fit exactly; page_size=20 means no pagination needed but the screen supports it for symmetry with T11): clamps at 1 and 20; the `Up, Up, Enter at 1 → captain=1` and `Down×30, Enter at 1 → captain=20` Done-when lines pin the clamps.
  - "GameState field default safety": existing tests construct `GameState` with positional args; adding two new fields with defaults must not break them. Verify by running the full test suite (`python -m unittest goal2.tests`) — any failure there is a T12 regression.
