# T03 The new game's players: a per-country model that matches the original seed-exactly

- **Kind**: slice
- **Issue**: #9 ·
  **Branch**: `task/T03-new-game-players` · **Merge after**: T02
- **Implementer**: the main session
- **Reviewer**: `luna` (the model is a static analysis of F007's listing traces, not an
  engine seam; the lighter reviewer fits)
- **Evidence**: F007 (the new-game player creation, behavioral across 12 main-screen
  savestates E006-r0001..r0012). The model's per-field writers are listed in
  F007's table; the data tables (DS:118A, DS:0E80) come from `ds_2581_01.hex`. The
  country record is read from `GOAL.DAT` (T02); the LCG is F004 (already vendored
  in T01). The fidelity oracle is E006-r0001's published main-screen savestate
  on archaeology's E006 release.
- **Owns**: `goal2/game/new_game.py` (the model), `goal2/tests/test_new_game.py`
  (the model tests, the LCG seeding, the E006-r0001 fidelity test).
- **Scope**:
  1. The LCG: reuse the vendored `LCG` from `goal2/engine/quick_engine.py` (T01).
     F004's `seed = seed·0x7ABD + 0x1B0F` is the same arithmetic; the seed per
     country is `c` (F007).
  2. The model: `make_country_players(goaldat, c)` returns a list of 20
     20-byte player records for country `c`, in the byte layout F007 documents
     (+0 country, +1 age, +2 peak, +3 potential, +4 current ability, +5 ?, +6/+7
     position, +8..+0B 0, +0C ?, +0D/+0E ?, +0F ?, +10/+11 0, +12 word fitness).
     The draws are `LCG.rand(7)`, `LCG.rand(3)`, etc. — in the order F007's table
     names.
  3. The full array: `make_all_players(goaldat, managed_country)` returns the
     3061-record player array (countries 1..128, plus the 80 managed-country
     players in records 2561..2640 per F007, plus the 0 records 2641..3060).
     The rating `rating(c) = ((5 - [+0x2C]) · (33 - [+0x2A]) + (129 - [+0x2B])) idiv 2`
     uses the country record's +0x2A / +0x2B / +0x2C bytes (F007; the country
     record is at `[DS:A917]` plus `COUNTRY_SIZE · c`).
  4. The fidelity test: downloads E006-r0001's main-screen savestate, reads
     the player array, runs the model with country 7 (Denmark) as the managed
     country (per F007's record 7 + manager 1), and asserts every byte matches.
     Per the E006-r0001 record, the managed country is country 7 (Denmark).
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_new_game` is green against the released
     GOAL.DAT and the E006-r0001 main-screen savestate (skipped with the reason
     when either is absent).
  2. The fidelity test compares all 3061 player records byte-for-byte against
     E006-r0001's player array; 0 mismatches.
  3. `python3 -c "from goal2.game import new_game; from goal2.data import goaldat;
     d = goaldat.load(open('.cache/GOAL.DAT', 'rb').read());
     ps = new_game.make_all_players(d, managed_country=7);
     print(ps[0])"` prints the first country's first player (record 0, which is
     all zero per F007), and `ps[1]` prints country 1's first player — same bytes
     as E006-r0001's first player of country 1.
- **Hazards**:
  - never commit a savestate (rule 19); `.cache/` is git-ignored; the test
    downloads from `gh release download E006`;
  - the LCG draws must happen in F007's order (per player, in the table's
    sequence); an out-of-order draw cascade into a different seed and a
    different country;
  - the rating computation uses the country record's bytes, not a hard-coded
    value; a wrong field index silently gives the wrong rating;
  - the position table (F007's GOAL.DAT block 10, byte `20c + slot − 1`) is what
    sets the player's +6/+7 bytes; loading it from `GOAL.DAT` (not hard-coding)
    is what makes the model country-accurate;
  - the managed country's 80 players (2561..2640) are made by a separate routine
    (F007's 98C4, with its own seed `0xf5db` from one LCG step past the last
    squad). This is in scope for T03 — without it, the model cannot reproduce
    the 80 managed-country players in E006-r0001.
