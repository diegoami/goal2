# T156 Capture an uninterrupted playthrough of the original

- **Kind**: infrastructure (design phase #524, stage 1)
- **Issue**: #525 · **Branch**: `task/T156-captures` · **Merge after**: none
- **Evidence**: [designed: owner, 2026-11-02, #524] "We have a process to explore the game, play the game, take the
  screenshot, so start it from there." The process is `docs/original-game/capture-method.md`: goal2-archaeology's
  E031 `PlayDriver` under DOSBox-X and a private Xvfb display, one key or one timed wait per logged step, each
  screenshot rendered from the savestate read right after, with hashes. Today's 63 images come from separate
  sessions (`docs/original-game/README.md`), and `docs/original-game/coverage.md` lists the gaps.
- **Owns**:
  - `docs/original-game/captures/` (new run logs);
  - `docs/original-game/images/` (new PNGs);
  - `docs/original-game/image-provenance.tsv`, `coverage.md`, and a new chapter `docs/original-game/playthrough.md`;
  - `measurements/T156/`.
- **Scope**:
  1. **One uninterrupted run** of the original from its title, through a new career, to the end of the first
     round and the start of the next. On the way:
     - management: squad, pool, tactics, captain;
     - the first match watched, half time with one substitution, full time and the summary;
     - the other results, the bulletins and the world turn;
     - a save, a quit, and a reload of that save.
  2. **The gaps in `coverage.md`** that one more run can reach (for example the managed-side goal replay prompt,
     injured and suspended player cards, the Championship results view). Each is logged the same way; what stays
     out of reach is named.
  3. **`playthrough.md`:** the run as a player would read it. Each step's screen, the key pressed, and what it does,
     in order, plus a one-page map of the flow (screens and the keys between them).

  Original files and savestates stay out of this repository (CLAUDE.md rule 14); only the PNG renders, logs and
  hashes are committed, as for the M244 runs.
- **Done when**:
  1. `docs/original-game/captures/` holds the new run's log. Every step names one key or one timed wait, with the
     before and after screen digests. `python3 tools/check_links.py` passes, and every new image is embedded in a
     chapter.
  2. `image-provenance.tsv` lists every new PNG with its run, step, source-state hash and PNG hash. A script in
     `measurements/T156/` recomputes the PNG hashes from the committed files and matches them.
  3. `coverage.md` is updated: each gap is closed with its image, or stays listed with why it was out of reach.
  4. `python3 tools/check_premerge.py --expected-head <sha>` passes.
- **Review**: the owner reads `playthrough.md` before T157 starts.
- **Hazards**:
  - A multi-key burst logged as one step (the capture method forbids it).
  - An original byte or savestate committed.
  - Working in `/home/diego/projects/goal2-archaeology` (another session's): use the engine clone
    `/home/diego/projects/goal2-archaeology-engine` read only, and run captures under `/tmp`.
