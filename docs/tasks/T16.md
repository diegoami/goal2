- **Owns**: `goal2/main_loop.py` (the driver); `goal2/loop.py` (the CLI entry); `goal2/tests/test_main_loop.py`.
- **Scope**:
  - `goal2.main_loop.run_main_loop(goaldat, state, savestate_path, keys=None) -> int`:
    1. Calls `run_country_select(goaldat, keys, state=state)`; on `None` (Esc), returns `0` without calling the next screen.
    2. Calls `run_squad_select(goaldat, keys, state=state)`; on `False` (Esc), returns `0`.
    3. Calls `run_tactics_select(goaldat, keys, state=state)`; on `False` (Esc), returns `0`.
    4. Calls `run_result(savestate_path, keys, state=state)`; on `False` (Esc), returns `0`. T14's `run_result` already surfaces engine refusals (A-MATCH-2/3) as the stand-in's refusal line.
    5. Prints a one-line "next fixture" placeholder to stdout (text is derived from `state.managed_country`, not a hardcoded literal) and returns `0`.
  - `goal2.loop` is the CLI entry point: `python -m goal2.loop <savestate> <goal.dat>` mirrors `python -m goal2.play` (T01's contract). Loads `GOAL.DAT` via `goal2.data.goaldat.load`; loads the savestate via `goal2.game.state.from_savestate`; calls `run_main_loop`; exits with its return code.
  - Out of scope (follow-ups, in priority order):
    - Applying user choices (`starting_eleven`, `captain`, `country_tactics`) into the match's savestate before running the engine. The vendoring follow-up (`state.to_savestate` should write `starting_eleven` / `captain` / `country_tactics`, per the T15 PRs note) lands first.
    - Per-position computer picking (Q035) — T15's top-11-by-ability stand-in is sufficient for the chain.
    - Real fixtures (A-COMP-1..9) — P5 work; T16's "next fixture" is a one-line placeholder.
    - Real watched engine (M1–M6) — T14's stand-in is the result screen.
    - Pool view, swapping players, rearranging the eleven — T12 follow-ups.
- **Done when**:
  1. `python -m unittest goal2.tests.test_main_loop` is green.
  2. `run_main_loop` calls `run_country_select` first, with `state` passed through. (Test asserts via mock spy: one call, `state` argument is the driver's `state`.)
  3. After `run_country_select` returns the chosen country number, `state.managed_country` reflects it. (Test runs the driver with a key sequence that lands on country 7, asserts `state.managed_country == 7`.)
  4. The driver calls `run_squad_select`, `run_tactics_select`, `run_result` in that order, passing the **same** `state` to each. (Test asserts the call order and that all four calls share the same `state` object — passing a fresh state to any screen makes the test fail.)
  5. On `None` / `False` (Esc) from any screen, the driver returns `0` without calling the later screens. (Test mocks country_select to return `None`; asserts squad_select, tactics_select, run_result are not called.)
  6. The driver prints a "next fixture" placeholder computed from `state.managed_country` before returning — deleting the placeholder line leaves stdout empty and the test fails. (Test captures stdout; the expected string contains the chosen country number.)
  7. `python -m unittest discover -s goal2/tests -p "test_*.py"` is green (full test suite — no regressions).
  8. `python -m goal2.loop <savestate> <goal.dat>` runs end-to-end with a scripted `keys` sequence and exits `0`; the screens render in order; stdout shows the country chosen, the placeholder at the end. (Test or scripted smoke; the sequence is the keys `[]` for an instant-return on each screen, then the placeholder — designed so the loop runs every call.)
- **Hazards**:
  - "Driver calls screens but doesn't thread state" — the screens write to `state` (per their own contracts); a fresh state per screen discards the writes. Test 4 catches this.
  - "Esc from one screen continues to the next" — short-circuit on `None` / `False`. Test 5 catches this.
  - "Placeholder message is hardcoded" — derive it from `state.managed_country` (e.g. `"next fixture: country {managed_country}"`); deleting the interpolation makes the test fail because the captured string differs from the expected value.
  - "Driver swallows engine refusals (A-MATCH-2/3)" — T14's `run_result` already renders the refusal line itself; the driver does not need to. (No test for refusals in T16; that's T14's contract.)
  - "Driver reads from stdin when `keys is None`" — the screens already do; the driver does not. The driver passes `keys` through unchanged.
  - "CLI entry imports the wrong module" — `goal2.loop` imports `goal2.main_loop` (the library), not the other way round. Mirror `goal2/__main__.py`'s `from goal2.cli import main` shape.
  - "The driver has no way to step in `step k of n` for a watching run" — T16 is a library function called from a CLI; the CLI runs it as one block. A future task can wrap the loop in a step-by-step driver for debugging.
