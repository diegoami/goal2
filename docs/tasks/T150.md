# T150 Re-vendor the sealed engine and build its tables from the player's GOAL.EXE

- **Kind**: infrastructure
- **Issue**: #480 · **Branch**: `task/T150-sealed-engine-vendor` · **Merge after**: the handover PR #479
- **Evidence**: goal2-archaeology milestone `m9-port-sealed-engine` (#629 there, reviewed AGREE at
  `b11171f7`), plus #640 there (the review's SHOULD findings #638/#639, merged after the tag); the
  handover `docs/handover-2026-10-30-sealed-engine.md` and upstream `docs/handover/T80.md`.
  [designed: owner, 2026-10-29] the tables are built on the player's machine from the player's own
  GOAL.EXE and never committed or shipped.
- **Owns**: `goal2/engine/original_match/**` (vendored), `goal2/engine/tables/**` (vendored),
  `PROVENANCE.md`, `goal2/game/engine_tables.py`, `goal2/tests/test_engine_tables_t150.py`,
  `goal2/tests/requires.py` (a `TABLES` requirement), `docs/artifacts.md`.
- **Scope**: Re-vendor upstream `runtime/original_match/` (the kit, its `port/` and `port/tables.py`)
  at upstream `main` with #640 merged, byte-for-byte, every file pinned in `PROVENANCE.md`. Vendor the
  tables generator unedited into `goal2/engine/tables/`: `tools/static/port_tables.py`,
  `tools/static/unlzexe.py` and `static/goal-exe/tables/manifest.json` (positions and digests only).
  `goal2/game/engine_tables.py` (written here) builds the tables once with the vendored `extract`
  (passing the vendored manifest; it refuses any other build) into a git-ignored folder, by default
  `.cache/engine-tables/`, and loads them with `port.tables.load`; `python3 -m goal2.game.engine_tables
  --exe PATH [--out DIR]` does it from the command line. The registered GOAL.EXE (upstream
  `.cache/artifacts/goal2-a949da2f/GOAL.EXE`) is added to the owner's Drive folder as `GOAL.EXE`
  (`tools/artifacts.py`), so CI and fresh checkouts can pull it. The match route is unchanged here: the
  original engine still plays every match (T151 switches it).
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_engine_tables_t150 -v` fails on `main` and passes after:
     the tables built from `.cache/GOAL.EXE` load and equal what `Image.state_of` needs (a reference
     image seals and its `build_problems()` is `[]`); a GOAL.EXE with one byte changed in a table slice
     is refused; the default output folder is git-ignored (`git check-ignore`).
  2. `python3 tools/check_provenance.py` passes, with every file under `goal2/engine/original_match/`
     and `goal2/engine/tables/` byte-equal to upstream at the pinned commit (the test of item 1 or a
     separate one compares them against the archaeology checkout).
  3. `git ls-files | grep -iE '(^|/)(ds|code_data)\.hex$|GOAL\.EXE$'` prints nothing.
  4. `python3 tools/check_premerge.py --slow --expected-head <sha>` passes (the re-vendor changes the
     engine every watched and competitive test runs); Linux and Windows CI green.
- **Review**: none (milestone).
- **Hazards**: editing a vendored file to make it importable (wrap it from `goal2/game/` instead: the
  generator adds its own directory to `sys.path` only when run as a script); committing the built
  tables; a re-vendor that silently changes behaviour goal2's tests pin: a test that changes result is
  reported, never adjusted to pass.
