# T92 Rename a player and the manager

- **Kind**: feature (first release, lane 3)
- **Issue**: #293 · **Branch**: `task/T92-rename` locally (a cloud session uses its own branch) · **Merge after**: T91
- **Evidence**:
  - [confirmed: goal2-archaeology `docs/play-guide.md` at 53d7ef5, E031 C30/C30b] **F2** renames the player on the card. The prompt says "maximum 12", and the first key replaces the old name.
  - [confirmed: same, C15/C15b] The manager name is typed at a new game: "Type in characters (maximum 14)".
  - [inferred: archaeology `spec/customisation.md` C-ALT-07] An in-game rename persists in the saved game, not in `GOAL.DAT`.
  - [designed: owner, 2026-10-21] Renaming is in the first release. Renames are kept in the session save. The manager name is in the same slice.
- **Owns**:
  - `goal2/game/identities.py` (new), `goal2/game/state.py` (two fields), `goal2/game/session_save.py` (version 4).
  - `goal2/desktop/model.py` (names resolved through the state), `goal2/desktop/squad_page.py`, `goal2/desktop/overview_page.py` and `goal2/desktop/window.py` (the actions).
  - `goal2/tests/test_identities.py` (new), `docs/desktop-management.md`, `docs/redesign-253/vision-reconciliation.md` (lane 3).
- **Scope**:
  - **Storage and resolution**
    - The state holds `player_renames` (player number → surname) and `manager_name`, both empty by default.
    - One resolver gives every view the renamed surname. The initial stays: the card shows "initial surname". [designed: whether the original's F2 also replaces the initial is not traced.]
    - The manager name replaces "Manager 1" in the top bar, on the Country desk and in Launch.
  - **Save format**
    - A session with any rename saves as **version 4**: version 3 plus an `identities` object.
    - A session without renames saves exactly as before, byte for byte. Versions 1–3 load unchanged.
  - **Validation**
    - A name is stripped of spaces at both ends and must not be empty.
    - It must be at most 12 characters (player) or 14 (manager), each printable CP437.
    - Cancel changes nothing. A name equal to the original removes the rename.
  - **Actions**
    - **Rename (F2)** on Team renames the selected player.
    - **Manager name** on the Country desk renames the manager.
    - Both apply to the active game at once, like the original. A preview or a running match refuses. The game becomes unsaved.
    - No record, XI, captain, tactics, campaign or RNG value changes.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_identities -v` shows each of the following:
     - Validation edges: 12 and 13 characters, 14 and 15 characters, empty, spaces only, non-CP437.
     - A renamed surname appears in the Team roster, card and table, the Pool, the Country desk captain line, the result's goal list and the watched match's completion ratings (the pitch names arrive with #262 and read the same resolver).
     - Save → resume keeps the renames and the manager name.
     - An unrenamed session encodes to the same bytes as before T92.
     - Versions 1–3 still load, and a malformed `identities` object is refused.
     - A rename equal to the original removes the entry.
     - Preview and busy states refuse.
     - The encoded state, apart from `identities`, is unchanged by a rename.
  2. The retained desktop scenarios pass (the T91 list) at `QT_SCALE_FACTOR` 1.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes (it runs the slow tests: saves change).
- **Review**: one review (saves).
- **Hazards**:
  - Never write `GOAL.DAT` or the template.
  - Never change a player record to carry a name.
  - The resolver must not copy names into a second store that can go stale.
