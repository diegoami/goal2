# T157 Screen and flow design from the original's captures

- **Kind**: design (design phase #524, stage 2)
- **Issue**: #526 · **Branch**: `task/T157-ui-design` · **Merge after**: T156 (and the owner's reading of its playthrough)
- **Evidence**: [designed: owner, 2026-11-02, #523, #524] Today's window departs from the original's flow, and the owner
  could not find how to play a match. The original's flow and screens are documented in `docs/original-game/`
  (T156's playthrough first). The earlier vision (#266, `docs/redesign-253/`) is input, not a constraint.
- **Owns**: `docs/design/ui-2026-11/` (the design document, its mockups and images).
- **Scope**: A design the owner can approve before anything is rebuilt.
  1. **The player's journey,** from first start (the import, T153) to a played season, as a flow of screens. Each
     screen is mapped to the original screen(s) and capture(s) it replaces, with the same decisions in the same
     order. Where goal2 adds or merges something (resume, import, the bot), the document says so and why.
  2. **Every screen:** its purpose, what it shows, the actions and their keys (the original's keys kept wherever
     they exist), and a mockup at desktop size.
  3. **Rules for the whole UI:** navigation, the primary action on each screen, how the match is watched, text
     size, colours, and the keyboard.
  4. **What today's window keeps, changes and drops,** screen by screen.

  The mockups are static images or HTML, not app code. Technology is T158's; this task assumes none.
- **Done when**:
  1. `docs/design/ui-2026-11/README.md` covers points 1–4. Every original screen in `docs/original-game/screen-inventory.md`
     and T156's playthrough is mapped to a new screen, or listed as dropped with a reason; a script checks this
     mapping against the inventory and reports nothing missing.
  2. Every new screen has a mockup that the document embeds.
  3. `python3 tools/check_links.py` passes.
  4. The owner approves the design on #526; changes are revised in this task.
- **Review**: the owner.
- **Hazards**:
  - Designing from today's window instead of the original.
  - Choosing a toolkit inside the design (that is T158).
