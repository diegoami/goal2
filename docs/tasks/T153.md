# T153 First-run import of the player's data folder

- **Kind**: feature
- **Issue**: #508 · **Branch**: `task/T153-first-run` · **Merge after**: T147
- **Evidence**: [designed: owner, 2026-11-02] The portable build gets its original-game files through a
  first-run import, never inside the ZIP (CLAUDE.md rule 14). The Core starts from a recorded emulator state
  (`e039-r0005-date-call.sav`, docs/core.md) that holds GOAL.EXE in memory, and it reads `GOAL.DAT`
  [confirmed: F032] (`goal2/core/runner.py:89`). Those files are the owner's private data folder, the one
  `tools/artifacts.py pull` fills (docs/artifacts.md); a player's own goal install cannot produce the
  recorded state. So the import takes such a data folder, and it serves the owner's playtest. Distribution
  to other players waits for GOAL.EXE to be out entirely (long-term, m3).
- **Owns**:
  - `goal2/desktop/data_setup.py`
  - the desktop's entry (`goal2/desktop/__main__.py`), for the default paths only
  - `goal2/tests/test_first_run_t153.py`
  - `docs/packaging.md` (the player's section)
- **Scope**: The data folder is per-user: `%LOCALAPPDATA%\goal2\data` on Windows, `~/.local/share/goal2/data`
  elsewhere. Saves go to `...\goal2\saves` beside it. On start without `--data`/`--core-boot` and without
  a complete data folder, the desktop shows a dialog that:
  - asks for a folder holding the required files;
  - checks each by SHA-256 against a committed list of names and hashes (hashes only, no bytes; the list of
    what the desktop's default start needs);
  - copies them into the data folder;
  - names what is missing or wrong in plain words.

  Then it starts as `python3 -m goal2.desktop` does today, with those paths as defaults. Explicit
  arguments still win, and developers' `.cache/` runs are unchanged.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_first_run_t153 -v` fails before and passes after:
     - a complete folder is imported and verified;
     - a missing file and a wrong hash are each refused, naming the file;
     - a second start goes straight in;
     - explicit `--data` bypasses the import;
     - nothing is written outside the data folder.
  2. The T147 ZIP, unzipped fresh on Windows: first start, import the owner's data folder, a new career,
     one watched match, save, quit, restart, resume. Recorded in `measurements/T153/`.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows and Linux green.
- **Review**: none (the owner's playtest).
- **Hazards**:
  - Committing a hash list that is mistaken for the files.
  - Overwriting a career on re-import.
  - A path written relative to the working directory.
