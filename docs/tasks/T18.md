# T18 Main loop saves user state before run_result

- **Kind**: feature
- **Issue**: #40 · **Branch**: `task/T18-apply-choices-to-match` · **Merge after**: T17
- **Implementer**: the `implementer` subagent on `haiku` (this session runs on MiniMax; `haiku` resolves to MiniMax-M2.7, the light model — T10–T17 worked on this alias)

- **Evidence**:
  - T17 (PR #39) vendored `country_tactics` at country record `+0x2D`, `captain` at `+0x2F`, `starting_eleven` implicit via `managed_squad[:11]`. The writes land in `raw_countries`, then `_write_countries` writes the array to memory at the country array's DS-prefixed location.
  - The vendored quick engine (`goal2/engine/quick_engine.py` line 187–190) builds its per-country table from `carr` (the country record array) directly: `"tactics": carr[base + 0x2D]`. For the managed country, `base = managed_country * COUNTRY_SIZE`. So the engine reads the same byte the state adapter writes.
  - `goal2/engine/savestate.py::Savestate.__init__(path_or_bytes)` already accepts either a path or bytes — no signature change needed for the engine side.
- **Owns**: `goal2/main_loop.py` (driver); `goal2/loop.py` (CLI); `goal2/tests/test_main_loop.py` (driver tests); `goal2/tests/test_state.py` (engine-picks-up-bytes test); possibly `goal2/ui/result.py` (docstring cleanup only).
- **Scope**:
  - `goal2.main_loop.run_main_loop(goaldat, state, original_savestate_bytes, keys=None) -> int`:
    - The third parameter changes from `savestate_path: str` to `original_savestate_bytes: bytes` — the bytes the loader read from disk before `from_savestate` ran. The CLI (`goal2/loop.py`) already has these bytes in `state_bytes`.
    - Step 4 (`run_result`) is preceded by `saved = state.to_savestate(state, original=original_savestate_bytes)`. Pass `saved` to `run_result` instead of the path.
    - All other steps unchanged: country_select, squad_select, tactics_select (which write to `state`), then save + run_result.
  - `goal2.loop.main` already does `savestate_file.read_bytes()` and stores it in `state_bytes`. Pass `state_bytes` to `run_main_loop` instead of `savestate_path`.
  - `goal2.ui.result.run_result` docstring update only (its `savestate_path` parameter is now sometimes bytes — `Savestate` already accepts both, no behaviour change).
  - `goal2/tests/test_main_loop.py`:
    - Existing tests use `"/fake/savestate"` for the path argument. Update to `b"<placeholder>"` for the bytes argument.
    - The new `state.to_savestate` call needs mocking. Add `patch("goal2.main_loop.to_savestate")` returning a stable byte string to the existing tests so they don't need a real fixture.
  - `goal2/tests/test_state.py` — new end-to-end test:
    - Build a `GameState` from a real fixture (or a saved fixture copied from `.cache/`); set `state.country_tactics = 0x42`; build `Savestate(state.to_savestate(state, original=original_bytes))`; build the engine (`QuickEngine`); read the engine's `countries[managed_country]["tactics"]`.
    - Assert it equals `0x42`. Mutation: skip the `to_savestate` call (pass `original_bytes` to `Savestate` instead) — the engine reads `0x8B` (E006's original), not `0x42`; the test fails.
  - Out of scope:
    - Per-position computer picking (Q035) and change-tactics-when-behind loop — T15 follow-ups. (The engine reads `squad[:11]` for the eleven; the captain is UI-only; these follow-ups are independent of this task.)
    - Real watched engine (M1–M6) — T14 follow-up.
    - Real fixtures (A-COMP-1..9) — P5.
    - The pool view, swapping players, rearranging the eleven's order — T12 follow-ups (would change what bytes reach the engine; out of scope here).

- **Hazards**:
  - "Driver calls screens but doesn't save before `run_result`" — the unit tests' `assert_called_with` on the mocked `run_result` proves the saved bytes reach the engine, not the path.
  - "Save fails on bad bytes" — `to_savestate(state, original=...)` requires `original` to be a valid DOSBox-X zip with Vga + Memory entries. Unit tests mock `to_savestate` so they don't need a real fixture. The end-to-end test uses a real fixture.
  - "Engine's `carr[base + 0x2D]` reads from a different byte after the save" — the byte at `raw_countries_arr[mc * COUNTRY_SIZE + 0x2D]` lands in the memory component via `_write_countries`; the engine's `carr` is constructed by reading that same memory component. The byte round-trips; the engine sees the user's choice.
  - "Captain byte still doesn't reach the engine" — the engine does not read a captain byte (T14's note). Captain persistence is for state fidelity / UI, not engine input. A comment in the code (or in the PR body) noting this is enough; do not over-promise engine behaviour for captain.
  - "`to_savestate` is a test mock that bypasses the actual save" — the end-to-end test must use the real `to_savestate`, not the mock. The unit tests mock it; the end-to-end test does not.
