# T149 Checkpoints and resumable work

- **Kind**: infrastructure
- **Issue**: #470 · **Branch**: `task/T149-checkpoints` · **Merge after**: none
- **Evidence**: [confirmed: #308 comment 6442836606] a hand-written handover held PIDs, run IDs,
  heads and next actions in prose; [confirmed: CLAUDE.md rule 11a] waits must use PIDs.
  [designed: owner, 2026-10-29] work has checkpoints and can stop and resume flexibly.
- **Owns**: `tools/jobs.py`, `tools/checkpoint.py`, `goal2/tests/test_checkpoints_t149.py`,
  `docs/process.md` (a "Stop and resume" section), `AGENTS.md` and `CLAUDE.md` (resume pointers).
- **Scope**: `tools/jobs.py start <name> -- <cmd>` runs a long job detached, recording name, PID,
  command, git head, start time and log under the git-ignored `.cache/jobs/`; its wrapper records exit
  code and end time. `list` shows each job as running, finished (with exit code) or vanished (PID gone
  with no exit record); `wait <name>` waits by PID; a running name cannot be started twice.
  `tools/checkpoint.py` prints a live snapshot (each listed checkout's branch, head and cleanliness,
  open PRs with heads, checks and labels, registered jobs) and with `--post "<next action>"` posts
  it to the open issue labelled `checkpoint`. The docs point to that issue's latest comment, not a
  pinned comment URL, and say when to checkpoint: before stopping, after a merge, when starting a long job.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_checkpoints_t149 -v` fails before and passes after:
     start/list/finished exit code; a killed job reported vanished; duplicate running name refused;
     wait returns on PID exit; the snapshot names branch/head/dirty state and PR head/check states
     (GitHub calls stubbed); `--post` targets only the `checkpoint`-labelled issue.
  2. `python3 tools/checkpoint.py` runs in this checkout and prints the snapshot.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows green.
- **Review**: none.
- **Hazards**: waiting with `pgrep -f` (rule 11a); recording secrets in job command lines; a
  snapshot that silently omits a failed GitHub call instead of saying it failed.
