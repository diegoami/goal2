# T159 The engine process and its pipe protocol

- **Kind**: infrastructure
- **Issue**: #533 · **Branch**: `task/T159-engine-pipe` · **Merge after**: T158
- **Evidence**: [designed: owner, 2026-11-03, #527, D3] The window talks to one long-lived PyPy engine process over
  a pipe. The protocol is in `docs/design/technology-2026-11/README.md` §3.4. The bugs it removes are in §3.2.
  The measurements are in `measurements/T158/engine-*.json`. The prototype is `tools/tech_probe/pipe_child.py`.
  Today's worker is `goal2/game/watched_worker.py`, with `goal2/desktop/competitive_worker.py` beside it. Today's
  parent is `goal2/game/watched_jobs.py`.
- **Owns**:
  - `goal2/game/engine_server.py`: the child, `python -m goal2.game.engine_server`.
  - `goal2/game/engine_process.py`: the parent side.
  - `goal2/tests/test_engine_pipe_t159.py`.
  - A section in `docs/desktop-management.md`, or a new `docs/engine-process.md`, describing the protocol.
- **Scope**: Build the engine process and its protocol. Nothing in the window uses it yet: T160 moves the watched
  and competitive matches onto it, and T161 moves the quick friendly and deletes the file journals. The task
  protects one claim: **a match played over the pipe is the same match the driver plays.** Its events, pitch
  samples, bench decisions and outcome must equal `_drive_match` on the same game, fixture and options.
  1. **The child** is started once under `engine_python()`, PyPy 3.11 (`goal2/game/engine_python.py`). Its stdin
     and stdout carry length-prefixed packets: a 4-byte big-endian length, then UTF-8 JSON. A binary payload
     follows its header, its size declared in the header.
     - Requests: `open` (the encoded game, `goal2.game.session_save` encoding); `match` {kind: watched or
       competitive, fixture, options, frames, bench}; `ack` {sample}; `pause`; `answer` {decision, substitutions};
       `cancel`; `quit`.
     - Replies: `ready`, `opened`, `event`, `frame`, `decision`, `answered`, `pause_dropped`, `complete` {outcome},
       `cancelled`, `error` {text}.
     - Watched and competitive matches use the same preparation and driver calls as the two workers today
       (`prepare_watched`/`prepare_competitive`, `_drive_match`, `substitutions=(5, 5)` for competitive), with the
       same LEAD pacing on acknowledged samples and the same pause and answer rules as `BenchPolicy`.
     - Nothing else of the child writes to stdout. Diagnostics go to stderr.
  2. **The parent**, `EngineProcess`:
     - It starts the child, sends requests, and reads replies on a reader thread. Each reply goes to a callback
       with no Qt dependency in `goal2/game`; T160 turns it into a Qt signal.
     - It is bounded: packet size limit; one match at a time; tokens are not needed, because one pipe is ordered
       and private.
     - End of the child's stdout, or its exit, is reported once as the engine's death with its exit code and the
       tail of stderr. The next `open` or `match` starts a new process.
     - `close()` sends `quit`, waits briefly, then kills.
  3. **Cancel:** `cancel` is read wherever the child already reads commands: each paced sample and each decision
     wait. The child replies `cancelled` and stays up for the next match. A cancel the child does not answer
     within a deadline is ended by killing the process. That counts as a death, and the next match starts a new
     one.
  4. **Window death:** end of the child's stdin makes the child exit, including while it waits for an answer or
     an ack (#417).
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_engine_pipe_t159 -v` passes, and fails on `main` because the modules do
     not exist. It shows:
     - **Framing:** a packet round-trips, payload included; an oversized or truncated packet is refused with a
       clear error, never a hang.
     - **Same match:** one watched match with frames and one competitive match over the pipe equal `_drive_match`
       for the same game, fixture, seed and options, run through `goal2.tests.pypy_engine`. Equal means events,
       pitch samples and outcome (result and memory digest).
     - **The bench:** a watched match with `bench` asks its first decision over the pipe. The test answers with a
       substitution and gets `answered`. A `pause` is honoured after a definite sample, or `pause_dropped` is
       reported. Each of these equals the same choices made through `goal2.tests.pypy_engine.drive`.
     - **One process:** two matches in a row are played by the same child (same pid), with `open` sent once.
     - **Cancel:** a match cancelled at its first event replies `cancelled`, and the next match on the same pid
       completes.
     - **Engine death:** killing the child mid-match reports death once, with its exit code. The next `match`
       starts a new pid and completes.
     - **Window death:** closing the child's stdin while it waits for a decision answer ends the child within 5 s.
     - **Interpreter:** the child reports itself as PyPy 3.11, and no test plays a match in the test process
       (`goal2/tests/__init__.py`'s guard stays on).
  2. The existing worker tests still pass unchanged: `test_watched_jobs`, `test_desktop_competitive_jobs`,
     `test_watched_bench_t102`, `test_pypy_worker_t152`. Nothing is moved off them in this task.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows and Linux green.
- **Review**: none (m3 milestone review).
- **Hazards**:
  - **Two drivers.** Re-implementing the match loop in the server instead of calling `_drive_match` and the same
    preparation as the workers. The equality test exists to catch exactly this.
  - **Pipe deadlocks.** Writing a large reply while the parent is blocked writing a large request. The parent
    reads on its own thread, and the 26.7 MB game goes in one `open` per game, not per match.
  - **Stray output.** A `print` or warning in the child corrupts the stream. Send diagnostics to stderr, and test
    that stray stderr output does not break the protocol.
  - **Windows.** Use binary mode on both ends, with no newline translation. The child is started with
    `stdin=PIPE, stdout=PIPE, stderr=PIPE`, and stderr is drained on its own thread so it never fills.
