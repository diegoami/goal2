- **Owns**: `goal2/ui/input.py` (key input abstraction), `goal2/ui/country_select.py` (the screen); `goal2/tests/test_country_select.py`, `goal2/tests/test_input.py`
- **Scope**:
  - The key input abstraction (`goal2.ui.input.Key`, `goal2.ui.input.read_key`):
    - `Key` is an enum: `UP, DOWN, ENTER, ESC, PAGE_UP, PAGE_DOWN`. [designed: the keys the country select screen needs; the squad screen (T12) and tactics screen (T13) reuse this set]
    - `read_key() -> Key` reads one key from stdin. Arrow keys arrive as `\x1b[A` / `\x1b[B`; PageUp/PageDown as `\x1b[5~` / `\x1b[6~`; Enter as `\n` or `\r`; Esc as `\x1b`. Raises `EOFError` on end-of-input (the test suite does not call this — it passes scripted keys).
    - The screen takes a `keys: Iterable[Key]` parameter (the test surface). When `keys` is `None`, the screen calls `read_key()` in a loop. [designed: scripted keys for tests, stdin for real use]
  - The country select screen (`goal2.ui.country_select.run_country_select`):
    - Signature: `run_country_select(goaldat: GoalDat, keys: Iterable[Key] | None, *, initial_country: int = 1, page_size: int = 20, state: GameState | None = None) -> int | None`
    - Renders the country list, paginated by `page_size` (default 20). Each page shows `page_size` countries starting at `page * page_size + 1`. 128 countries → 7 pages of 20 (last page has 8).
    - Cursor on `initial_country` (1..128). Clamps out-of-range values to `[1, 128]`.
    - `Up` / `Down`: move cursor by ±1; clamps at 1 (Up does nothing) and 128 (Down does nothing).
    - `PageUp` / `PageDown`: jump by `±page_size`; clamps at 1 and 128.
    - `Enter`: if `state` is given, set `state.managed_country = cursor` and `state.managed_squad = list(goaldat.squad_20[cursor])` (20 bytes). Then return `cursor`. [confirmed: F011 writes the choice to the country's record; the rebuild writes the choice to the adapter's `managed_country` / `managed_squad` fields]
    - `Esc`: return `None`. If `state` is given, leave it untouched.
  - Rendering (the test surface):
    - Title row 0: `SELECT COUNTRY  N/128` where N is the cursor (1..128, padded to 3 chars). [designed: the original's title bar is unknown; this is the rebuild's]
    - Body rows 1..page_size: one country name per row, left-justified, padded to 80 chars. The cursor's row uses reversed video (the grid's `draw_text` with `fg=0, bg=7`).
    - Footer row 24: instructions — `↑↓ SELECT  PgUp/PgDn PAGE  ENTER PICK  ESC QUIT`. [designed]
  - Out of scope: window renderer — T12+; the squad screen — T12; the tactics screen — T13; the result screen — T14; multi-manager country lists — the country picker is one country at a time (F011's full manager pool is a follow-up).
- **Done when**:
  1. `python -m unittest goal2.tests.test_country_select goal2.tests.test_input` is green.
  2. `test_country_select` asserts, with a `GoalDat` whose `country_names[1..3]` are `["ALPHA", "BRAVO", "CHARLIE"]`:
     - `run_country_select(goaldat, [DOWN, ENTER], initial_country=1)` returns `2` and (if `state` is given) sets `state.managed_country == 2`.
     - `run_country_select(goaldat, [ESC], initial_country=5)` returns `None` and does not touch `state`.
     - `run_country_select(goaldat, [PAGE_DOWN, ENTER], initial_country=1, page_size=20)` returns `21` (the first country of page 2).
     - `run_country_select(goaldat, [UP, UP, ENTER], initial_country=1)` returns `1` (clamped at 1; two Ups at the boundary are not an error).
     - The expected country for each scripted key sequence is computed from the input (cursor movement), not a hardcoded literal — so deleting the cursor logic makes the test fail.
  3. The render surface test: after `run_country_select(goaldat, [ENTER], initial_country=7)` is set up (use a generator that yields one key then EOF, or a test that calls a private `_render(grid, cursor, page_size, goaldat)`), the rendered grid has the cursor row's first cell at column 0 holding the country name at index 7 (the cursor's country) and the title row holding `SELECT COUNTRY   7/128`. The expected name and number are computed from the input — deleting the cursor argument leaves a different row.
  4. `test_input` asserts `Key` has the six enum values; `read_key` is callable (not invoked in tests).
  5. `state.managed_squad` is set to a 20-element list when `Enter` is pressed with `state` given; the bytes equal `goaldat.squad_20[cursor]` byte-for-byte.
- **Hazards**:
  - "Test passes with the grid deleted" (lesson from T05/T09/T10 review rounds): the expected country number and name are computed from the input, not literals — so deleting the cursor logic fails the test.
  - "Off-by-one at the page boundary" (lesson from F011: 80 pool records fit exactly; 128 countries in pages of 20 leaves 8 on the last page): the screen clamps at 1 and 128; `Up` at 1 is a no-op; `Down` at 128 is a no-op; `PageDown` from page 6 (countries 121..128) does nothing. The Done-when 2 `Up, Up` at 1 pins the clamp; a `Down, Down, Down` at 127, 128, 128 would pin the lower clamp too.
  - "Squad length is not 20" (the bytes 11..19 of each squad-20 record are distinct from bytes 0..10 per F011; a misread could give 11+9): assert `len(state.managed_squad) == 20` in the Done-when 5 test.
  - "State write is silent": assert `state.managed_country == cursor` after Enter, not just the return value.
  - "Key iteration off-by-one": a generator that yields `[ENTER]` and then EOF must not run any further iterations; the screen returns after the Enter.
  - "Title row / footer row collide with body": row 0 is the title, rows 1..page_size are the body, row 24 is the footer. With page_size=20, the body fills rows 1..20 and the footer is row 24 (rows 21..23 are blank). With page_size=25, the body fills rows 1..25 and the footer would overlap — clamp page_size to ≤ 23 in code, or document that page_size>23 is a misuse. The Done-when uses page_size=20.
