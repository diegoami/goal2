# T152 The match worker under PyPy 3.11

- **Kind**: infrastructure
- **Issue**: #482 · **Branch**: `task/T152-pypy-worker` · **Merge after**: T151
- **Evidence**: [designed: owner, 2026-10-29, CLAUDE.md] the plain port runs under PyPy 3.11 as goal2's
  engine runtime, a PyPy match-engine process beside the CPython/PySide6 UI; same results (goal2-archaeology
  #620: E034-03, F40, T79's 700 matches), about 4 times CPython's speed.
- **Owns**: `goal2/game/engine_python.py`, the worker launch sites (`goal2/game/watched_jobs.py`,
  `goal2/desktop/competitive.py`), the worker modules' imports, `goal2/tests/test_pypy_worker_t152.py`,
  `.github/workflows/ci.yml` and `windows.yml` (a PyPy 3.11 install), `docs/` setup pages,
  `measurements/T152/**`.
- **Scope**: The watched and competitive match workers start under PyPy 3.11 when it is available
  (`GOAL2_ENGINE_PYTHON`, else a `pypy3.11` found on PATH or in uv's managed Pythons), else under
  `sys.executable`, as now. A worker imports nothing PySide6 or pygame needs. CI installs PyPy 3.11 and
  runs the worker under it. Out of scope: shipping PyPy in the portable build (a packaging task).
- **Done when**:
  1. `GOAL2_SLOW=1 python3 -m unittest goal2.tests.test_pypy_worker_t152 -v` fails on `main` and passes
     after: a watched match job and a competitive one run through their workers under PyPy give the same
     outcome as under CPython; with no PyPy, the worker falls back to `sys.executable`.
  2. The CPU time of one match under each interpreter is recorded in `measurements/T152/`.
  3. `python3 tools/check_premerge.py --slow --expected-head <sha>` passes; Linux and Windows CI green.
- **Review**: none (milestone).
- **Hazards**: a worker import that drags in Qt; a PyPy found on the machine that is not 3.11; the
  fallback hiding a broken PyPy setup (log which interpreter ran).
