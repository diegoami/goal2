# T158 Technology choice for the rebuilt UI

- **Kind**: design (design phase #524, stage 3)
- **Issue**: #527 · **Branch**: `task/T158-technology` · **Merge after**: T157's first draft (it can start alongside)
- **Evidence**: [designed: owner, 2026-11-02, #524] "a solid design phase, both for the ui, screens and also for the
  technology to use."
  - Today: PySide6 on CPython for the window; matches in a PyPy 3.11 worker over file channels (#516); the Core route
    runs the original under Unicorn (#509, #507's correction); the pitch view in a pygame process.
  - goal2rust's hybrid runs about 30% faster than PyPy (#516's comment).
  - The owner's m3 decisions (#509): GOAL.EXE out entirely; GOAL.DAT read from the install first, replaced later;
    goal2rust in parallel.
- **Owns**: `docs/design/technology-2026-11/`, `tools/tech_probe/` (throwaway prototypes and probes), `measurements/T158/`.
- **Scope**: A recommendation the owner can decide on, made from prototypes and measurements, not opinion. It
  absorbs T154 (#516).
  1. **The UI toolkit.** At least PySide6 (today) and one web-technology option (a local web UI or a desktop shell
     around one). Others where they fit T157's design. Each is judged on:
     - drawing T157's screens and the pitch;
     - keyboard-first play;
     - Windows packaging size and start time;
     - accessibility;
     - running the engine beside it.

     A prototype of the same two screens, the manager menu and the captain stop to kick-off, in each candidate.
  2. **Which route becomes the game.** Grow the Python route (already on the port) into the full game, with the Core
     as a test oracle, or bridge the port into the Core (#509, question 1). Say what each costs in tasks and what it
     waits on upstream (#427).
  3. **The engine boundary** (T154's scope): an inventory of today's channels, the bugs they caused, and
     measurements on Linux and Windows of today's file channel against a long-lived engine process over a pipe,
     and against goal2rust's hybrid as a CPython module.
  4. **Packaging:** what the portable ZIP becomes for each choice.
- **Done when**:
  1. `docs/design/technology-2026-11/README.md` covers points 1–4, ends with a recommendation and its costs, and
     names the owner's decisions.
  2. `measurements/T158/*.json` hold the raw timings and sizes. The document's tables are computed from them by a
     quoted command.
  3. Each prototype in `tools/tech_probe/` starts with one documented command on Linux and on Windows, and the
     document shows a screenshot of each.
  4. `python3 tools/check_premerge.py --expected-head <sha>` passes.
  5. The owner decides on #527.
- **Review**: the owner.
- **Hazards**:
  - A prototype that grows into the product: prototypes stay in `tools/tech_probe/` and are deleted after the
    decision.
  - Timings on a loaded PC: record the load, and run with nothing else heavy on it.
