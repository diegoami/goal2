# T147 Wheel verification and portable Windows ZIP artifact

- **Kind**: infrastructure
- **Issue**: #468 · **Branch**: `task/T147-package` · **Merge after**: T146
- **Evidence**: [designed: owner, #432 comment 6440424797] build-only Nuitka 4.1.1 and declared build
  dependencies are approved in an isolated environment/CI; the portable Windows batch is required.
- **Owns**: `.github/workflows/package.yml`, `tools/check_wheel.py`, build-only configuration it
  needs, `goal2/tests/test_package_t147.py`, `docs/packaging.md`, `measurements/T147/**`.
- **Scope**: A workflow (PRs touching packaging, `main`, dispatch) builds the wheel in an isolated
  environment, installs it into a fresh one without the source tree, and `tools/check_wheel.py`
  checks that `goal2` imports, its entry point starts, its package data is present and every
  vendored `goal2/engine/` file in the wheel matches its `PROVENANCE.md` pin. A Windows job builds the
  portable ZIP with Nuitka 4.1.1 from that isolated environment, smoke-starts the executable without
  original files (it must say what is missing, not crash), and uploads the ZIP as a run artifact
  with the original-extension refusal. No release, tag or publication.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_package_t147 -v` fails before and passes after
     (`check_wheel.py` passes on a good wheel and fails on one missing package data or with an
     altered vendored file).
  2. A green package run with the wheel check log and the ZIP artifact; the ZIP's file list contains
     no original-game file (`measurements/T147/run-<id>-v1.json`).
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows and Linux green.
- **Review**: none for the wheel check; the owner's Windows playtest judges the ZIP.
- **Hazards**: build tools leaking into the runtime dependencies; testing the wheel from the source
  tree; an original file baked into the ZIP.
