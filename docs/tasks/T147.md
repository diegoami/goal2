# T147 Portable Windows ZIP: bundled CPython and PyPy, playable from the folder

- **Kind**: infrastructure
- **Issue**: #468 · **Branch**: `task/T147-package` · **Merge after**: T152
- **Evidence**: [designed: owner, 2026-11-02, superseding the Nuitka build of #432 comment 6440424797]
  The portable build bundles Pythons instead of freezing goal2. It holds the official embeddable CPython 3.13
  for the UI, with goal2 and its dependencies, and PyPy 3.11 for the match workers (CLAUDE.md, owner
  2026-10-29). The workers and the pitch viewer start as `python -m ...` subprocesses
  (`goal2/game/engine_python.py`, `goal2/desktop/jobs.py`, `goal2/desktop/watched.py`), which a frozen
  .exe cannot run; bundled interpreters run them unchanged. Nothing of the original game ships
  (CLAUDE.md rule 14). The player's data comes in through T153.
- **Owns**:
  - `.github/workflows/package.yml`
  - `tools/build_portable.py`
  - `tools/portable/**` (the launcher and pinned download manifest)
  - `goal2/tests/test_package_t147.py`
  - `docs/packaging.md`
  - `measurements/T147/**`
- **Scope**: `tools/build_portable.py` builds `goal2-<version>-win64/`:
  - `python/`: the CPython 3.13 embeddable distribution, its `._pth` enabling `site-packages`, with goal2
    from its wheel and the `desktop`, `watched` and `match-view` extras installed.
  - `pypy/`: the PyPy 3.11 Windows release, which reaches goal2's code. The match workers import only
    goal2's pure-Python modules.
  - `goal2.cmd` (or a tiny launcher): sets `GOAL2_ENGINE_PYTHON` to the bundled `pypy\pypy.exe` and starts
    the desktop with `python\pythonw.exe -m goal2.desktop`, passing its arguments through. It runs from any
    working directory and any path, spaces and non-ASCII included.

  Every download is pinned by version and SHA-256 in a manifest, and the build refuses a mismatch.
  Then it zips the folder.

  A Windows job (on PRs touching packaging, on `main`, on dispatch) builds it on the hosted runner and
  runs the packaged smoke from a copy in a directory with spaces, with no Python or Git on PATH:
  1. The launcher's `--help` exits 0.
  2. The bundled PyPy answers as PyPy 3.11.
  3. One watched match played through the packaged runtime equals the same match played from the source
     tree. It uses the original files the workflow pulls into `.cache/`, outside the folder that gets
     zipped.

  It then checks that the ZIP's file list holds no original-game file (the existing extension refusal
  and the T145 originals check) and uploads the ZIP as a run artifact.

  **Out of scope:**
  - T153: the first-run import of the player's data folder.
  - An installer, signing, updates.
  - Any release, tag or publication.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_package_t147 -v` fails before and passes after:
     - the build lays out a folder from given inputs;
     - it refuses a download whose SHA-256 differs from the manifest;
     - it refuses an original-game file in the folder;
     - the launcher sets `GOAL2_ENGINE_PYTHON` to the bundled PyPy and passes its arguments through.
  2. A green package run with the ZIP artifact, in which:
     - the packaged smoke's three checks pass from a directory with spaces and no Python or Git on PATH;
     - the ZIP's file list contains no original-game file;
     - ZIP size, build time and the packaged match's time are recorded in
       `measurements/T147/run-<id>-v1.json`.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows and Linux green.
- **Review**: none for the build; the owner's Windows playtest judges the ZIP (with T153).
- **Hazards**:
  - Testing the packaged runtime against the source tree on `sys.path`.
  - A DLL or Qt plugin missing only on a clean machine.
  - An original file baked into the ZIP.
  - PyPy picking up the UI's `site-packages`.
