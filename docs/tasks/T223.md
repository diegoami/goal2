# T223 The original's delay, at the time it asks for

- **Kind**: fix (core pacing; v0.1)
- **Issue**: #428, and #455's pause after a miss · **Branch**: the session's `claude/…` branch in a cloud session,
  locally `task/T223-delay-wall-time` · **Merge after**: T222
- **Why**: [designed: owner, 2026-11-13, #705] v0.1 fixes #455 and #428; pacing work on the Unicorn path is allowed
  for this release only.
- **Evidence**:
  - [confirmed: #455 comment 2026-10-27T09:15:47Z, native Windows; archaeology 53d7ef5 `seg_0791_01.c` 0791:0441,
    `seg_214B_02.c` 214B:1EF1/1F87] The owner's 3–4 s pause after a wide shot, at speed 2, is 3.47 s inside the core
    worker: 22 calls of the calibrated delay `214B:1E09` from 0791:043B (argument 2, the per-slot pacing), one from
    214B:1EB2 (1, the beep) and **1,708 from 214B:1F81 (1, `play_note` in `play_jingle`, the whistle)**. The core
    ignores speaker output (runner.py NG-10), so the pause is an unheard whistle executed as a busy loop.
  - [confirmed: F030; `goal2/core/runner.py:24`] Timed prompts are counts of key polls with `214B:1E09(10)` after
    each; they read no clock. The replay prompt after a goal is 600 such polls (#429, closed: the prompt is shown).
  - [confirmed: `goal2/core/views.py` `match_speed`, F030 0791:9372] The speed is the original's delay 0..5; 0 has no
    delay.
  - [derived] `214B:1E09` is Turbo Pascal's `Crt.Delay(ms)`: for each millisecond, a loop of the calibrated count
    (set at boot; where it is kept is for the task to find: T222 showed DS:7B4A is the heap end, not this count) that also ends if the BIOS tick at 0040:006C changes. Its wall time under Unicorn is
    the emulator's speed, not the milliseconds the original asks for: the cause of #428's "slowest settings are
    excessively slow" and of the miss pause's length. To be shown by the task, not assumed.
- **Owns**: the core's handling of `214B:1E09` (`goal2/core/runner.py` or a module beside it), the watched match's
  pacing in `goal2/desktop` (core_model / core_window / core_viewer), `docs/core.md`, its test
  `goal2/tests/test_core_delay_t223.py`.
- **Scope**: the task protects one claim: **the core spends, in wall time, the milliseconds the original's delay
  asks for, and the game it plays is unchanged.**
  1. At `214B:1E09`'s entry, the core runs no loop: it leaves the routine with the registers, flags, stack and
     memory the loop would have left (the proof is item 1 of Done-when), and reports the milliseconds asked.
  2. The watched match waits those milliseconds of wall time before the original continues (a whistle's jingle
     takes its ~1.7 s; a timed prompt its polls × 10 ms). Headless runs (tests, quick results, the season) keep
     running at full speed: the wait is the window's, not the core's.
  3. While the original waits for a sound, the window says so (for example "whistle") so a stop never looks
     frozen. No sound is played (#431 stays out of scope).
  4. Speeds 0..5 keep their original meaning; nothing is relabelled.

## Done when

1. `python3 -m unittest goal2.tests.test_core_delay_t223` passes and failed before: for each speed 0..5, a watched
   first half from the same new game played (a) executing every delay and (b) with the delay served gives the same
   waits, frames, commentary, score and DS at half time. (Under `GOAL2_SLOW=1` if it is slow; then a bounded case
   — the wide shot's transition and a goal with its replay prompt — runs in the fast gate.)
2. Measured on Linux and recorded under `measurements/T223/`: for each speed, the wall time of the same watched
   stretch before and after, and the milliseconds the original asked for. The core's own time per delay served is
   under 1 ms.
3. The window shows a note while a sound's delay runs, and the replay prompt counts down at its original pace;
   offscreen test.
4. The owner's Windows playtest (#705's gate) says the speeds and the pause after a shot are right. Until then the
   task reports this line as not verified.
5. `python3 tools/check_provenance.py` and `python3 tools/check_premerge.py --expected-head <sha>` pass.

- **Hazards**:
  - **The tick ends the loop early.** If any caller relies on the BIOS tick changing inside a delay, serving it by
    count alone changes the game. The equality run of Done-when 1 is what rules this out; do not shorten it.
  - **Never skip a poll.** Timed prompts are polls; only the delay between polls is served.
