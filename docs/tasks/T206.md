# T206 `artifacts.py pull NAME` writes the file under its own name

- **Kind**: fix
- **Issue**: #683 · **Branch**: `task/T206-artifacts-pull-name` · **Merge after**: —
- **Evidence**:
  - [confirmed: observed while capturing the build's manual, T204 #664] `python3 tools/artifacts.py
    pull e039-r0005-date-call.sav` left `.cache/goal2drive:e039-r0005-date-call.sav`, and every
    later run looked for a file that was not there. It was worked around by hand twice.
  - The cause is in `tools/artifacts.py`: a drive remote ends with `:` (`artifacts.json`'s
    `drive.rcloneRemote` is `goal2drive:`), so the joined source `goal2drive:NAME` holds no path
    separator and `Path(...).name` returns the whole string. The destination was taken from that
    joined source.
  - The unnamed form (`pull` with no names, which copies the folder) was never affected.
- **Owns**:
  - `tools/artifacts.py`: the pull destination.
  - `goal2/tests/test_artifacts_pull_683.py`.
- **Scope**: The task protects one claim: **a named pull writes `localDir/<the name given>`, for
  every shape of remote.**
  1. `pull_commands(cfg, names)` returns the rclone arguments a pull runs, so the destination can
     be tested without the network, and the destination comes from the name the caller gave.
  2. `main` runs those arguments. Nothing else of the tool changes: `push`, `where` and the
     whole-folder pull keep their behaviour.

## Done when

- `python3 -m unittest goal2.tests.test_artifacts_pull_683` passes, and fails if the destination is
  taken from the joined source again.
- `python3 -c "import sys;sys.path.insert(0,'tools');import artifacts;from pathlib import Path;print(artifacts.pull_commands({'remote':'goal2drive:','localDir':Path('.cache')},['GOAL.DAT'])[0][-1])"` prints `.cache/GOAL.DAT`
- `python3 tools/artifacts.py where` still prints the folder, the remote and the local directory.
