# T155 Playing the next match is obvious (playtest fixes)

- **Kind**: fix (bug #523)
- **Issue**: #523 · **Branch**: `task/T155-play-next` · **Merge after**: T153
- **Evidence**: [designed: owner, 2026-11-02, #523] The owner's playtest of the portable ZIP hit three problems:
  - after a new career, how to play the next match is not clear;
  - "Watch this match" (`goal2/desktop/fixtures_page.py:602`) is a checkable toggle that does not start the match;
  - the match will not start without a captain, and nothing says so.

  The captain choice itself is the original's [confirmed: `docs/original-game/match-and-results.md`,
  `images/captain-select.png`], so it stays. T143 preselects the original's best captain.
- **Owns**: the Core route's main window and round page (`goal2/desktop/core_window.py`,
  `goal2/desktop/fixtures_page.py`, and the pages they use for this flow), `goal2/tests/test_play_next_t155.py`.
- **Scope**: The smallest change to today's window that removes the three problems. The full UI is redesigned later
  (#524); do not restructure pages.
  1. The main window shows one primary control to play the next match. It is visible on the window's first page
     after a new career or a resume, and it leads to the round's first stop.
  2. Watching is chosen by the action that starts the match. Example: "Kick off and watch" next to "Kick off, quick
     result". No control looks like an action but only toggles a setting.
  3. At the captain stop the suggested captain is selected and shown, so one action kicks off. The page says in
     words that the captain can be changed and how.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_play_next_t155 -v` fails on `main` and passes after:
     - from a new Core career's main window, the play-next control is visible without navigation, and it reaches
       the captain stop;
     - at the captain stop, with nothing else changed, the watch action kicks off watched, with the pitch viewer
       started and the suggested captain;
     - the quick action kicks off unwatched;
     - no checkable button on the round page is labelled as an action.
  2. Existing round tests still pass: `test_core_round_t108`, `test_core_watch_t109`, `test_core_captain_t143`,
     `test_core_replay_t140` and `test_core_match_window_t138`, with `GOAL2_SLOW=1`. Any assertion they make about
     the old toggle is changed only where it encoded the toggle itself, and the PR lists each one.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes; Windows and Linux green.
