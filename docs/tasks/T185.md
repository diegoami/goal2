# T185 Pause the watched game while reading commentary

- **Kind**: owner correction · **Issue**: #597 · **Branch**: `task/T185-commentary-pause`
- **Merge after**: none
- **Evidence**: [designed: owner playtest2026-11-05, #592] “SPACE Commentary should pause the game.”
  The current binding only toggles commentary visibility; the watched match continues while read.
- **Owns**: `goal2/ui/s17_pitch.py`, small playback helpers if necessary,
  `goal2/tests/test_commentary_pause_t185.py`, relevant UI docs.
- **Scope**: Space opens a clear commentary reading pause; Space again resumes the same watched
  game or replay with its normal pacing. The displayed clock, released events and painted sample
  sequence stay fixed while paused; no further frame acknowledgements escape. The engine may
  finish its already admitted LEAD window but cannot publish a completed career behind the pause.
  Resume rebases the display clock and never skips samples to catch up. Keep existing goal,
  bench/refusal and captain/question holds; no extra engine decisions, inputs or RNG draws.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_commentary_pause_t185 -v` fails before and passes after:
     real Space and clicked key-bar controls share one path, visibly say paused/resume, freeze
     clock/events/sample acknowledgements, and resume without a burst or missing sample.
  2. An actual PyPy watched match with commentary pauses has exactly the same final state, result,
     events and RNG as the same uninterrupted match with identical game answers. Replay pause
     preserves its sample order. Questions retain their hold and quick-result behavior is explicit.
  3. Existing replay/pitch/bench controls pass; main runs the clean final-head gate and required CI.
- **Hazards**: hiding text without pausing; old next-frame timestamps causing catch-up; acknowledging
  a final goal behind a reading pause; making Space dismiss a held question inadvertently.
