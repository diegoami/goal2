# T145 Layout and page-reserve checks first in the pre-merge gate

- **Kind**: infrastructure
- **Issue**: #466 · **Branch**: `task/T145-layout-first` · **Merge after**: none
- **Evidence**: [confirmed: Windows run 40785633279, job 123157983963] T144's T107/T141 page-reserve
  failures take about 8 s to run but were reported only at the end of a run of about an hour.
  [designed: owner, 2026-10-29] Cheap layout checks run before the expensive simulations.
- **Owns**: `tools/check_premerge.py`, `goal2/tests/test_premerge_layout_t145.py`, `measurements/T145/**`.
- **Scope**: `check_premerge.py` names a fixed set of layout/reserve test modules, chosen from the
  modules that check page bounds or the 90 % reserve and whose whole run (slow tests included) is
  measured as short. The gate runs them first, always with slow tests, in parallel; any failure
  ends the gate before the full batch, with every failing module's output. The full batch then
  runs the remaining modules, so nothing runs twice and nothing is dropped. Windows and Linux CI
  get this through the gate itself; no workflow edit. The claim protected: no test module is
  skipped or weakened, and a layout regression fails the gate within a minute of the tests starting.
- **Done when**:
  1. `python3 -m unittest goal2.tests.test_premerge_layout_t145 -v` fails before and passes after:
     every named layout module exists and checks bounds or reserve; the layout stage runs first and
     with slow tests on even when the gate's slow choice is off; a failing layout module stops the
     gate (non-zero, its output printed, full batch never started); with all passing, the full batch
     runs every other module exactly once and the summary counts every module.
  2. `measurements/T145/before-89be1f37-v1.log`: the new gate on T144's unfixed `89be1f37` source
     (a scratch archive) fails in its layout stage, naming T107 and T141, before the full batch.
  3. `python3 tools/check_premerge.py --expected-head <sha>` passes, and the Windows workflow is green.
- **Review**: none (tooling; no game behaviour).
- **Hazards**: dropping modules from the full batch without running them; running the layout
  modules without slow tests (T107's reserve case is slow-gated); choosing modules by guesswork
  instead of the measured timings.
