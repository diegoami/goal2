# Direction, owner decisions and unowned capabilities

[designed: owner, 2026-10-20] **The visual and experience direction is decided.** The owner accepted [vision #266 / PR #267](https://github.com/diegoami/goal2/issues/266#issuecomment-6287825622): the original GOAL2 is the visual baseline (black screens, strong functional colors, large characters, complete graphical bar cards, maximum-size match pitch, full commentary hidden by default with the latest two lines visible, independently retractable top and side bars). The authoritative description is [docs/vision-266/](../vision-266/README.md); the [reconciliation record](vision-reconciliation.md) maps this package to its nineteen screens. This document no longer asks the owner to choose or approve a direction, a look or a screen style. It records the choices that are still genuinely open, the deliberate departures from the original, and the capabilities that have no delivery owner.

## Approval gate

[designed: owner, 2026-10-20] The owner accepted the direction on #266 and approved the audit queue. Explicit owner direction approval is no longer outstanding. This package is a planning gate: the owner’s separate acceptance of this reconciled plan still precedes any implementation that depends on it, and no new child issue starts from it automatically. The accepted direction is not approval of this unchanged package, a toolkit or an architecture. **Plan acceptance is not implementation approval.** Filing, documentation review and merge are not that approval either. No toolkit, backend-language or architecture migration is authorized. Every implementation still follows the repository’s model-selection, worktree, task, independent review and exact-head merge process, after its own bounded preflight.

[designed: owner #253] Existing independently authorized work retains its own scope and authorization. This plan does not revoke T79/T84/T85 or any other independently authorized task; their visual contracts are reconciled to the accepted black, large-text, bar-based target on their own issues without rejecting useful lifecycle or decoding work. Adaptations wait for normal per-task authorization, without changing their active branches under this issue.
