## Lessons this run surfaced (worth formalising in `docs/lessons.md`)

These are observations, not rules yet — the next session or the owner
decides whether to record them.

- **L110 — regression-oracle grep must match all import forms.** T21's
  DW5 was `grep -RnE "goal2\.engine\.(new_game|skills|state)\b"` —
  the dot form. The doc DW3 examples used the `from X import Y` form,
  which the regex didn't catch. The implementer ran the narrow grep,
  got a clean pass, and missed the broken doc commands. The fix: a
  wider regex matching both forms
  (`grep -RnE "goal2\.engine\.(new_game|skills|state)|from goal2\.engine import (new_game|skills|state)"`)
  is the right regression oracle for "no leftover references". When
  a task moves a module, the oracle should be widened by default.
- **L111 — when a Done-when surfaces a pre-existing bug, report and
  amend, don't paper over.** T21's DW4 ran `divergence.py`, which has
  a misnamed identifier (`Path(ARCHAEOLOGY)` instead of
  `Path(ARCHAEOLOGY_ENV)`). The bug only fires when `GOAL2_ARCHAEOLOGY`
  is set, so the implementer (env unset) didn't see it; the reviewer
  (env set) surfaced it. The fix was a one-character edit in code the
  task didn't own (T19's); the right move was to amend the task on
  `main` with the reason and declare the fix as a one-file mechanical
  edit in Scope. The implementer's report should have flagged the
  discrepancy first; the main session can fix the script after.
- **L112 — docstrings that describe import patterns must be
  file-by-file literal, not aspirational.** The round-1 docstring
  claimed "the parent-form style is used everywhere" — a policy ideal,
  not a description of the code. The reviewer's rework-2 caught it
  because `state` is imported in *both* forms in the actual codebase.
  The fix in `75017c6` lists the actual file:line usage. Future
  docstrings that describe a pattern across files should be read as
  literal descriptions, not policy claims, and verified with a grep
  before commit.
