# #270 slice 1 (T86): the asset-free scenario seam

[designed: T86] This page names the existing seams that the fictional scenario lane
(`goal2/scenario/`) drives, the protocol rules it must keep, and a proposed split of
[#270](https://github.com/diegoami/goal2/issues/270)'s remaining slices. The split
is a proposal for the owner; nothing here schedules work.

**Claim protected.** [designed: T86] A fresh clone with no original resources, no
goal2-archaeology checkout and no PySide6/pygame/Unicorn can drive the existing
Qt-free model/controller/worker seams through a fictional, deterministic session.
That lane can never pass for, or publish into, a real career. A fake passing these
cases proves the controllers' protocol guards. It proves nothing about original RNG,
match fidelity or the original's rules.

## What the lane is, and what it is not

- [designed: T86] **Fictional data only.** Five invented countries (Northmarch,
  Eastvale, Southmere, Westholm, Lowfield) and 100 invented players, generated by a
  closed formula in `goal2/scenario/factory.py`. No GOAL.DAT name, savestate byte or
  executable byte is read or reproduced. `docs/vision-266/scenario.json` is an
  illustration and is **not** used.
- [designed: T86] **Scripted, not simulated.** Every score, goal minute, injury,
  board and pitch pose comes from a fixed script table (`goal2/scenario/scripts.py`).
  Poses are a closed arithmetic pattern with no football meaning. There is no second
  football simulation.
- [designed: T86] **Opt-in only.** The lane runs only through
  `python3 -m goal2.scenario` and the `goal2.tests.test_scenario_*` tests.
  `goal2.desktop.__main__` is unchanged. A missing `--data` file still exits with
  `Cannot open game` (or the PySide6 install hint), never a demo.
- [designed: T86] **No mock of PySide6, pygame or Unicorn.** The fake viewer is a
  separate child process that speaks the viewer status protocol. It reuses the real
  `match_view.Display` and the real `pygame_viewer.frame_digest` (pure functions, no
  SDL import). It does not stand in for the SDL module.

## The seams

[designed: T86] Each controller gained one keyword argument, `runtime=None`. With
`None`, the existing original path runs unchanged. The guard lines that existing
mutation recipes pin (`tools/desktop-ui/prove-*.py`, `tools/prove_*.py`) are
textually unchanged.

| Existing module | Injection point | What `runtime` supplies | Real code still exercised |
| --- | --- | --- | --- |
| `goal2/desktop/jobs.py` | `QuickJobs(model, command=, runtime=)` | `check(state, template)`, `encode`, `load` | one job at a time, halftime preview validation, the `swap` substitution draft, continuation once-only, stale-snapshot refusal, exit/early-publication rule, template/match-count binding, cancel/reap |
| `goal2/game/watched_jobs.py` | `WatchedJobs(owner, command=, runtime=)` | `publication(owner, competitive=)`, `encode` | private folder, `request.json`, length-prefixed journal, token/sequence checks, duplicate refusal, completion-equals-stream check, frame budget/watermark/ACK rules, publish only after exit, cancel |
| `goal2/desktop/competitive.py` | `CompetitiveJobs(owner, command=, runtime=)` | `require_competitive()`, `publication(owner, competitive=True)` | `pending_fixture` calendar binding, match-pending exclusion, all of `WatchedJobs` |
| `goal2/desktop/watched.py` | `WatchedController(model, engine_command=, viewer_command=, runtime=)` | `require_watch()`, `completion(outcome, names)`; passed on to `WatchedJobs` | friendly-only `fixture()`, `Display` journal, viewer status token/sequence/digest checks, rendered-frame ACK, completion packet |

[designed: T86] The scenario runtime is `goal2.scenario.runtime.ScenarioRuntime`. Its
`publication` is a subclass of the real `WatchedPublication`. The subclass inherits
`_pending_for`, `_check_owner`, `publish_prepared` and `cancel`, the once-only token
and stale-owner guards. It overrides only the two steps that need original memory:
`begin` (no original image is prepared) and the candidate builder.

### Data schemas the fakes conform to

- [derived: T86 from the existing code] **Quick halftime packet** (`halftime.json`):
  exactly `eleven, bench, available, captain, kind, removed, changes, score, teams`,
  as `QuickJobs.validate_halftime` requires. The continuation is `continue.json`, a
  list of `[outgoing, incoming]` pairs written by the real `write_json`.
- [derived: T86] **Watched journal** (`events`): 4-byte big-endian length, then JSON
  `[token, sequence, kind, value]` with `kind` in `event | complete | error`, written
  by the real `watched_jobs._write`. Events are `Event(kind, minute, score, data)`
  using kinds that the original adapter emits: `minute`, `commentary`, `goal`,
  `injury`, `decision`, `half_time`, `substitution`, `full_time`, `extra_time`,
  `shootout`, `shootout_kick`, `end`.
- [derived: T86] **Completed result**: the kit-2 result dictionary. It passes the
  real `watched_schema.validate_result` (friendly, or competitive with
  `resolution`/`validate_resolution`). The scenario publication runs that validator
  before it builds a candidate.
- [derived: T86] **Pitch frames** (`frames`): `[token, frame]` records written by the
  real `watched_pitch.write_frame`, each passing `watched_pitch.validate`; one frame
  per completed tick (`result['ticks']`).
- [derived: T86] **Viewer journal and status**: JSON lines `[token, sequence, kind,
  value]` accepted by the real `Display`; the status file is
  `{token, kind, sequence, digest[, frame_sequence, frame_digest]}`, replaced
  atomically.
- [designed: T86] **Model view**: `ScenarioModel.view()` returns the same keys as
  `DesktopModel.view()` (`countries, country, country_name, players, morale,
  play_label, fixture`; player rows `id, name, position, ability, energy,
  confidence, availability`). `pool_view()` keeps `squad, reserves, window`.
  Availability and morale come from the real `eligibility.info` and
  `campaign_confidence.team_morale`, applied to fictional 20-byte records in the
  rebuild's record layout. Full player cards are a separate `card(word)` view.

### Token, sequence, ACK and once-only publication

1. [derived: T86 from `watched_jobs.py`] `start` returns a fresh 48-hex token.
   Every journal record must carry it, and its sequence must equal the next
   expected number. Nothing may follow `complete`. A wrong token, a gap, a repeat
   or a second `complete` cancels the job without publishing.
2. [derived: T86] Completion is accepted only after the child has exited with code 0
   and the journal is fully read. The completion's events must equal the streamed
   events. With frames, the frame count must equal `ticks`. The last frame must
   also be acknowledged before publication.
3. [derived: T86] Frame ACKs are cumulative and strictly increasing, and only for a
   delivered frame. The viewer's status must name the controller's token and a
   sequence it has sent, with the matching digest. The status sequence may never
   go backwards.
4. [derived: T86] Publication swaps `owner.state` once, after `owner.view(candidate)`
   validates it. The owner must still hold the exact state object and value captured
   at `start`. Cancel invalidates the token first. A cancelled, stale or failed job
   never publishes.
5. [designed: T86] **Fiction mark.** A scenario state carries
   `scenario == 'goal2-fictional-scenario/1'`. Its template bytes are a fixed marker
   that is not a savestate, and its results carry `engine ==
   'goal2-scenario:fictional:1'`. The scenario codec refuses any file without the
   mark. The scenario publication refuses an unmarked owner, and `ScenarioModel.save`
   refuses outright. Real `session_save.save` and `DesktopModel.resume` reject
   scenario data, and real `QuickJobs` rejects scenario output for a model with
   another template. Scenario fixture identifiers keep the existing calendar schema
   (`original:<n>`), because `pending_fixture` binds to it. Fiction is identified by
   the mark, never by the identifier.

## Shared contract cases

[designed: T86] `goal2/tests/test_scenario_contract.py` defines each protocol case
once and runs it against two backends:

- **fake**: `ScenarioModel` + `ScenarioRuntime` + scenario workers; always runs.
- **real**: `DesktopModel.open(.cache/e010-r0008-halftime.sav, .cache/GOAL.DAT)` with
  the default runtime and the original workers. It runs only when those files exist,
  plus Unicorn for watched cases (`goal2.scenario.real.missing`). Otherwise each case
  prints `real backend: not configured (<missing items>)` and is reported as
  *skipped*, never as passed. Nothing is downloaded.

Fault workers (wrong token, gap, duplicate completion, early output, slow exit, crash)
read only `request.json` or argv, so the same fault runs against either backend.

## Known boundaries of this slice

- [confirmed: T86 run of `match_view.Display.lines()`] The real presentation's first
  line is always `Original engine — friendly`, so the fictional walkthrough's
  display lines carry it too. The programmatic marks above identify the fiction. A
  *visible* demo label is a UI decision for the slices that own the screens
  (#242/#260–#262). This slice does not edit the presentation.
- [designed: T86] The real-backend contract cases have not run in the cloud
  container that built this slice: GOAL.DAT, the E010/E006 savestates and Unicorn
  are absent. They turn on when slice 3 stages resources.
- [designed: T86] The fake children prove protocol handling, publication and the
  fiction boundary. They do not prove original RNG, timing or match fidelity, which
  remain the fidelity tests' job (CLAUDE.md rule 20).
