# goal2 0.1.0

[designed: owner, 2026-11-13, #705] goal2 0.1.0 is the first version for players: the portable Windows ZIP
`goal2-0.1.0-win64.zip`, for a player who has their own copy of *goal (version 2)* (New Era Software, 1993).

## What it is

The original game runs inside goal2, emulated under Unicorn, as goal2's core, and goal2's window shows it: the
management pages, the original's new game and bulletins, the pitch window for a watched match, the bench, and the
original's own choices read from its memory (docs/core.md, docs/desktop-management.md). [designed: owner, 2026-10-22,
#308; 2026-11-13, #705]

The ZIP holds goal2 and the two Pythons it runs on (the embeddable CPython 3.13 for the window, PyPy 3.11), and no
file of the original game (CLAUDE.md rule 14; docs/packaging.md). The player supplies two files from their own
install: **GOAL.EXE** and **GOAL.DAT** (GOAL.HLP is taken too when the folder has it). The first start asks for that
folder, checks each file against the released one's SHA-256 and copies them to `%LOCALAPPDATA%\goal2\data`; careers
are saved in `%LOCALAPPDATA%\goal2\saves` (docs/packaging.md, "The player's data folder"). Unzip it, double-click
`goal2.cmd`: no Python, installer or administrator rights are needed. The ZIP's `README.txt` says the same for
players.

## What it fixes

- **The core boots from the player's GOAL.EXE** (T222). Until now the core started from a recorded emulator state at
  the original's DOS date call, which no player has and which never ships. It now runs GOAL.EXE from its first
  instruction to that call, and the new game is the same game the recording gave [confirmed: T222's test,
  `goal2/tests/test_core_exe_boot_t222.py`; docs/core.md "Booting from GOAL.EXE"]. A GOAL.EXE of another SHA-256 is
  refused, naming the file.
- **The pause after a shot (#455) and the match speeds (#428)** (T223). The original paces its match with a
  calibrated delay loop (`214B:1E09`); under the emulator that loop took the emulator's time, not the milliseconds
  the original asks for, so a whistle's jingle stalled the match for seconds and the slow speeds were far slower than
  the original's. The core now serves the delay without running the loop, and the window waits the milliseconds
  asked, with the game unchanged [confirmed: T223's test, `goal2/tests/test_core_delay_t223.py`: the same waits,
  frames, commentary, score and memory either way; docs/core.md]. While the original waits for a sound the window
  names it, so the pause no longer looks like a freeze.
- **Tactics during a match (#454)** (T224). The window offers the team tactics, a player's own tactic and marking
  where the original offers them in a match (live play, through the original's pause; before the kick-off; at a
  stoppage or an interval), by the original's own keys [confirmed: T224's probe and test,
  `goal2/tests/test_core_in_match_tactics_t224.py`; docs/core.md "Tactics in a match (T224)"].
- **The ZIP for players** (T225): `goal2.cmd` is its only launcher; the player's README; the package workflow's
  smoke runs a player's first start from the ZIP on Windows (the import of GOAL.EXE and GOAL.DAT, a new career, one
  watched match to full time) [designed: T225; docs/packaging.md].

## Known limits

- **No sound** (#431). Where the original plays a sound the window waits for its length and names it.
- **Windows 64-bit only** for the ZIP; elsewhere goal2 runs from its source (docs/desktop-management.md).
- **The milestone review and the owner's Windows playtest follow publication** [designed: owner, 2026-11-13, #705],
  against the published build: before it, 0.1.0 is checked on Windows by the package workflow's smoke only.
- **The standalone engine is the direction after v0.1.** v0.1 ships the core route, the original under Unicorn, as a
  scoped exception; goal2's own engine (the plain port under PyPy) replaces it later, and careers of 0.1 need not
  carry over to it [designed: owner, 2026-10-27 and 2026-11-13, CLAUDE.md].
