# original_match: the original's watched match, played interactively on goal2's state

For a goal2 session. You need nothing of goal2-archaeology but this folder and one image goal2 already fetches.
The match is the original game's own code (`run_match` 0791:F1F6, then its post-match player update 0791:B7FA)
run under Unicorn; this kit answers the original's key reads, at the original's own decision points, with the
keys a manager would press. Nothing of the original is in this folder: its code and data come from the image.

## Get it (once)

1. **Vendor** this folder byte for byte into `goal2/engine/original_match/` and add a PROVENANCE row per file
   (source `diegoami/goal2-archaeology`, the commit you copied, findings F004 F010 F013 F014 F018 F026 F027 F028
   F029 F030, issue 250). Never edit it there; changes come upstream.
2. **unicorn** (approved, goal2 #97): `pip install unicorn` (2.1.x; Debian/Ubuntu: `python3-unicorn`). The package
   imports without it; only creating a `Match` needs it (a clear error otherwise), so goal2's quick path keeps
   working without it.
3. **The image** is goal2's own E006-r0001 (release E006, SHA-256 `e0afff67…657d`, the file
   `tools/measure_p1.py` fetches): `assets.reference_image(".cache")` fetches it with `gh` and checks its hash.
   Any savestate goal2 makes from it works too.

**The build guard.** Creating a `Match` runs `image.build_problems()` first and refuses an image whose engine is not
the registered GOAL.EXE's (set goal2-a949da2f, the file `static/goal-exe/` was made from). `build.py` holds the
registered executable's SHA-256 digests (positions and digests only, no byte of the original; generated by E033's
`build_guard.py`, never edited by hand), and the image's bytes are hashed the same way:
- **All the code**: image 00000..2580F (153,616 bytes, every routine, the RNG's constants included), one digest per
  4 KiB block (38). The image holds the code relocated (the load segment added to 1,916 words): the guard subtracts
  the image's own load segment from those words before hashing, so where DOS loaded the game does not matter, but any
  other change in a relocated word does.
- **The initialised data a match reads and never writes**: 10,169 bytes in 299 ranges inside DS:0000..7B6F (the
  depth, line, position, occupancy and threshold tables, the templates, the tactics rows...), the bytes nine
  matches with every kind of answer read and never wrote (E033 `ds_reads.py`), one digest per 1 KiB block of DS (24).

Not covered: initialised data none of those matches read; the variables (any byte a match or the game's start-up
writes); everything above DS:7B6F (the players, countries, fixtures, managers, seeds: goal2's state); everything outside
GOAL.EXE's image (the stack, the screens, the rest of DOS memory). goal2's `to_savestate` writes its "clock word"
at DS:0E6C, which is a byte of the original's foot table (DS:0E60..0E7B, read by 1771:3088; F008, F028; a covered
range): it must stay as the template has it, or the guard refuses.

Another build is refused with `ValueError("the image does not hold the GOAL.EXE this kit was made on (the registered
version, set goal2-a949da2f); it differs in: code 0000:0000..000E:0F1F; data DS:0400..07FF")`, naming each differing
block (here the first code block and the second data block). A savestate without exactly one GOAL program in DOS
memory is refused earlier (`N GOAL programs in the image's conventional memory (one is needed)`). `Match.load(blob)`
does not run the guard again: a saved match carries its own memory.

## Know it works

    python3 -m goal2.engine.original_match.check --cache .cache            # about 45 s
    python3 -m goal2.engine.original_match.check --cache .cache --family   # + about 110 s

`engine PASS`: E011-r0001's friendly replayed from the image is the match E021 recorded from the original's own
DOSBox-X run (score, 4,149 ticks, all 182,188 RNG draws by digest, the board, the last 199 commentary lines).
`interactive PASS`: the worked example below, played straight and saved/resumed at minute 60, is the same match
and the one this kit recorded. `goals PASS`: a quick result from minute 30 and seed 70's match with a goal taken
back have consistent goals (see Goals below). `family PASS`: E032's ten seeds are E032's records.

## Play a match

```python
import zlib
from goal2.engine.original_match import Image, Match, Fixture
from goal2.game.state import to_savestate, from_savestate, _rewrite_zip

image = Image.from_savestate(to_savestate(state, original=template_bytes))   # goal2's state, as it saves it
m = Match(image, Fixture(first=7, second=19, index=40),   # Denmark v country 19, calendar number 40
          managed=state.managed_country)
for ev in m.events():                                     # events as they happen
    show(ev)                                              # ev.kind, ev.minute, ev.score, ev.data
    if ev.kind == "minute" and ev.minute == 20:
        m.pause()                                         # a manager pressing Enter in play
    if ev.kind == "decision":                             # the original stops and asks
        d = ev.data                                       # context, eleven, bench, positions, injured, ...
        if d["context"] == "pause":
            m.answer(tactics={6: True})                   # stand ground
        elif d["context"] == "half_time":
            m.answer(substitutions=[(d["eleven"][9], d["bench"][1])])   # a second keeper: refused, d["refused"] on the next decision
        else:
            m.answer()                                    # play on
    if want_to_stop:
        blob = m.save(); break                            # at any event; Match.load(blob) continues it exactly
result = m.result()          # score, goals (goals_disallowed, goal_counts), bookings, injuries, substitutions, board, ...
after = m.memory_component() # the memory after the match and its post-match update: goal2's next state
next_state = from_savestate(_rewrite_zip(template_bytes, {"Memory": zlib.compress(after)}))
```

The calls: `Fixture(first, second, index=None, kind=1)` (team 0, team 1 = the host of a friendly; `index` None takes the
image's own fixture number); `Match(image, fixture, *, managed=None, captain=None, seed=None, players=None,
countries=None, ticks=False, record_draws=False, delay_byte=None, timeout_s=60)` (`managed` defaults to the image's
human country, `captain` to the original's pick; the last three are for the engine check); `m.events()`,
`m.answer(...)`, `m.pause()`, `m.save()`, `Match.load(blob)`, `m.result()` (once `m.over`), `m.memory_component()`,
`m.image()`, `m.pitch()`, `m.screen_text()`, and the read-only `m.over`, `m.score`, `m.minute`, `m.waiting` (the
decision the original waits on, or None). Errors: `MatchError` (the original or the state refuses; no decision
waiting), `ValueError` (a bad argument, another build), `GuestError` (the original did something the kit does not declare) and `ScreenError` (a screen did not move as
expected): the last two mean the kit stopped rather than guess.

`Match(..., players=..., countries=...)` writes record lists over the image's instead (goal2's `GameState.players`
and `.countries` as they are, without the squad order and tactics `to_savestate` applies). E033's
`goal2_trial.py` is this flow on goal2's own code (5.9 s, the result read back by `from_savestate`).

`python3 -m goal2.engine.original_match.example --cache .cache` runs the same kind of match from the reference
image (a pause, a half-time substitution, a save and resume at minute 60; about 9 s).

**Events**: `minute`, `commentary` (the original's line, with its template and players), `goal`,
`goal_disallowed` (the original takes back a goal it just wrote, in the same action), `booking`, `sending_off`,
`injury`, `substitution` (both teams), `half_time`, `full_time` (the board's statistics), `decision`, `tactics`,
`position`, `player_tactics`, `substitution_requested`, `refused`, `end`; `tick` too with `Match(..., ticks=True)`.
`m.pitch()` gives the 22 players' and the ball's positions at any moment (for drawing).

**Goals**: a `goal` is a goal the original commits. Watched, that is the score byte's `inc` at 0791:685C; a
`goal_disallowed` is its `dec` at 68B3 (DS:830E set: no scorer row), which comes after the `goal` and after whatever
the original wrote in between (its commentary), never in the goal's place. In a quick result (`answer(quick=True)`,
any `speed`) the quick engine 0791:D733 runs once a minute: it saves the score, clears DS:9B3C and rolls trial counts
into it (B19D, D8A5), then writes the committed score back at DA58 with at most one new goal (record_goal 6443).
Only that commit makes `goal` events; the trial counts make none, and every event inside the engine carries the
committed score. So in every path (watched, quick from any minute, after any answer, across `save()`/`load()`):
each event's score is the score of the goal events before it, a `goal_disallowed` follows a goal of its team, and
`result()["goals"]` holds, per team, the board's score and the original's own count (`result()["goal_counts"]`,
DS:80F0, record_goal's; it credits an own goal to the side whose score rises); the goals taken back are in
`result()["goals_disallowed"]`. `check.py`'s `goals` step tests this (`goal_problems`). A score write from any
other instruction in play (the action replay's restore 0F11 included, which no run of the kit reached) stops the
kit with `GuestError`, as does a write of any other event's counter from an instruction the kit did not read
(`WRITERS` in match.py).

**Stamps**: an event's `minute` and `score` are the guest's minute word (DS:831F) and score bytes (DS:9B3C, 9B3D)
at the moment of the original's own write that the event reports, and events come in the order of those writes
(not in the order the kit looks at them). The writes, from `play_match`'s start (the set-up before it resets them):
the commentary ring counter DS:80EE (a `commentary` line; 1D4A), a committed score byte going up (a `goal`, stamped
with the score after the write) or down in the same action (`goal_disallowed`, the take-back; see Goals), a team's bookings, red-card or
injury count (statistics row +7, +8, +9), the substitutions-left counter DS:9B3A + team (a `substitution`;
DS:9B38 is the action replay's copy, not it) and the minute word itself (`minute`, the new minute). What an event
carries besides the stamp (the line's text, the scorer, the players swapped) is read from the records those writes
completed. `decision`, `half_time`, `full_time`, `end` and what a screen did (`tactics`, `position`,
`player_tactics`, `substitution_requested`, `refused`) are stamped with the guest's minute and score when they happen.
**Order**: events come in the order of the original's writes across kinds, not only within a kind: no event is
moved or rewritten after it is queued, and a screen's or a decision's event comes after every write made before it.
The check (E033 `stamps.py`, 17 matches: the reference fixture, E032's ten seeds, a run with pauses and
substitutions and a goal taken back, an injury run, a run with sendings off, quick results from minutes 30 and 1 and
one after answers at minute 60) hooks the same guest writes independently of the kit's event path (the quick engine
by code hooks at its entry D733 and after its commit DA5B) and compares, per kind (and team where the kind has one),
the number of events and each one's minute and score, in order, for `commentary`, `goal`, `goal_disallowed`,
`booking`, `sending_off`, `injury`, `substitution`, `minute`, `half_time` and `full_time`, and then the whole stream
of those kinds against the writes in the original's order (`order`). It does not compare the stamps of the other
kinds or the details inside an event.

**Saving**: every public event is a save boundary: `minute`, `commentary`, `goal`, `goal_disallowed`, `booking`,
`sending_off`, `injury`, `substitution`, `half_time`, `full_time`, `decision`, `tactics`, `position`,
`player_tactics`, `substitution_requested`, `refused`, `end` and `tick`. `save()` accepts all of them, a `decision`
before `answer()` included (the loaded match has `m.waiting` set: answer it, as the original is still asking; taking
the next event unanswered plays on) and after it, and events queued but not yet taken are saved with it. Straight and
resumed are the same match: the remaining events (kind, minute, score, data) and the result are equal. No boundary is
refused on purpose. `save()` still raises `MatchError("save between events, not while the kit drives a screen")` if
called while the kit is inside one of the original's team screens, which goal2 cannot reach, as no event is taken
from `events()` in the middle of a screen. The check (E033 `save_boundaries.py`) saves and resumes at the first
event of every kind a run yields, at every decision before and after its answer and at the last event, over seven
scenarios (two fixtures, goal2 managing the other country, an injury run, a run with sendings off, a pause with
every kind of answer and a refused eleven, a quick result with `tick` events).

**Decisions** (where the original itself stops for the manager) and what an answer does there:

| context | when | substitutions | other answers |
| --- | --- | --- | --- |
| `half_time` | after the half-time board | made now | tactics, positions, marking, own tactics, quick, speed |
| `substitution` | at a stoppage after an injury to your player, or after you asked for one | made now; the default is what you asked for | as above |
| `pause` | when you call `m.pause()` | asked for: the original offers them at its next stoppage | made now |
| `extra_time` | before each extra-time half (competitive fixtures: not reachable, the kit refuses them) | made now | as above |

`answer(substitutions=[(off, on)], tactics={element: bool}, positions={player: code}, marking={player: opponent
or 0}, own_tactics={player: {element 1..4: True/False/None}}, quick=True, speed=0..5)`; no argument plays on.
If the original refuses the result (its message, e.g. "Denmark has too many goalkeepers"), the same decision comes
back with `refused` set; answer again. A declined injury notice comes back at every stoppage, as in the original.

## What the original decides for you (rules to know)

- **The seed is the fixture's**: the set-up reseeds the RNG with `index * (year + 1)` (0791:2648), so a fixture
  number plays one match for given teams and answers. `seed=` overrides it at kick-off (a deviation, declared).
- **The match depended on the two teams' records and nothing else in the image** on the fixture tried (E033: the
  stack and the screens zeroed, an image taken inside a match with the teams' records restored: the same match).
  The set-up writes into the computer side's records (it sorts its squad and sets its eleven's positions,
  0791:BC5D), so **carry the records forward**: the next match starts from `memory_component()` of this one, as
  the original's next fixture does.
- The computer's side is the original's: its lineup, tactics and substitutions. Your country is made the human's
  (`managed=`); the image's former human country is released as the original releases a sacked manager's.
- `speed` changed no match where checked (E011-r0001's fixture, the speed byte 0 and 1; the original reads it
  only for its delays and the speaker); it is the original's display speed, for goal2 to pace its own display.
- The post-match update runs (energy recovery, form and confidence from the result: F018, F019); the original's
  news pages after a fixture do not. Read the new player bytes from `memory_component()`.

## Limits and costs

Friendlies only (kind 1): `Match` refuses any other `Fixture.kind` with a `ValueError`, so the `extra_time` decision
and the shoot-out cannot be reached (checking them: about 2 h with E031's shoot-out state). The set-piece taker prompts keep the original's pick (exposing them: about 1 h). One
human side. A match costs 9-13 s (a quick result after `R`, about 4 s; the write hooks behind the stamps are included); stepping by
minute or tick adds nothing measurable. `save()` is about 0.36 MB at minute 60 (much more with `record_draws`, which keeps every RNG write).
